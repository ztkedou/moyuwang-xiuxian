## 2. 统一设计决策（八条）

1. **业务拒绝一律 400/409，绝不用 403**（铁律，`Xc()` 把 403 当会话失效强制登出）。师徒域存量已全合规（§1.1），新增端点沿用。
2. **申请-审批制，复用 `status='pending'` 预留位，零新表零加列**。审批 accept = 守卫式单语句 `UPDATE … WHERE status='pending'` + 全套门槛重验（并发双审批/审批瞬间满员只一方 changes=1）；decline/cancel/过期 = 置 `'declined'`（**不触发 7 天冷却**——冷却语义只属于 `expired`，存量冷却查询按 `status='expired'` 过滤（:6452 my、:6505-6506 INSERT 守卫），`declined` 天然不入冷却，零迁移）。
3. **申请有效期**：pending 行 `created_at` 超过 `MENTOR_APPLY_TTL_MS`（新常量，**定档 48h**，《数值表-T7T8》T8-7；与仙盟 72h 差异：师徒 1v1 + 等级差门槛 ⇒ 师傅必更活跃）视为过期——**惰性归档**（审批时拒绝置 declined + my 读取时顺手置 declined），不建定时任务（本项目零 cron 惯例）。
4. **动账全部服务端结算，沿用既有双原语 `updatePlayerSave`/`insertMail`**：请安/传功/出师回馈/抽成不经客户端 JSON（Y6B 定论，保持）。新端点零新增动账原语。
5. **所有数值集中在 `[mentorcore]` 常量区**（:4677-4688）+ 新增常量同区集中；本批全部新增数值**已于 2026-09-29 数值批定档**（《数值表-T7T8》：TTL 48h / 贺礼 base 3000 / 贺礼每徒每日 1 笔），调参不改逻辑。既有 12 常量一个不动。
6. **EV 红线不触发**：师徒无赔率类玩法（无下注/无中奖概率），请安/传功/出师回馈均为确定性服务端发放且存量已定档；本批不新增任何概率型产出。「新增」只落在**信息可见性 + 审批流 + 徒弟出师贺礼一份小额邮件**，不动 5% 抽成、×1.1 同行、×1.3 出师增益、30% 回馈的既有数值。
7. **玩法说明 = 客户端静态文案**（§7 全文，T7 同款折叠块），零新端点；数值优先用 `rules`/`consts` 下发值动态拼接，改常量文案自动跟。
8. **前端为第 18+ 号新模块 `yl_t8mentor_ext.py`，纯 ASCII 注入**（中文一律 `\uXXXX`，SKILL §14.2）；`V28_MODULES` 由架构师统一接线（fun086 之后、numbal 恒最后；与 act087/t6chardex/t7sect 新模块互不重叠锚点）。**实现员不跑 build/dryrun/sandbox**（工作流分工铁律）。

## 3. 玩法闭环设计（对应任务书：拜师条件 / 出师 / 传功 / 奖励 / 解约冷却 / 玩法说明）

### 3.1 拜师（改申请-审批制）

```
徒弟：搜索师傅（名字模糊）→ 选人 → [申请拜师] → pending 行建立 → 等待审批（可撤回）
师傅：师徒页签「收徒申请」卡 → [收纳] / [婉拒]
收纳 = 守卫式 UPDATE pending→active（门下<3、双方非冷却、申请未过期重验）→ 双方邮件
婉拒 = pending→declined → 申请人邮件
```

- **拜师条件不变**（存量 :6484-6496 预检 + :6496-6510 守卫）：师傅候选境界≥筑基期（`MENTOR_MIN_REALM_INDEX=1`）、总等级（境界序×9+层数，`MENTOR_LEVEL_STEP=9`）≥徒弟+5（`MENTOR_LEVEL_GAP=5`）、师傅门下<3 弟子（`MENTOR_MAX_APPRENTICES=3`）、双方均不在 7 天解除冷却、徒弟当前无 active 师傅。全部在**申请时**校验一次、**审批时**重验一次（守卫式单语句）。
- **C1 改造** `POST /api/mentor/apprentice`（:6476）：INSERT（:6502-6510）的 status 字面量由 `'active'` 改 `'pending'`，守卫条件逐字保留（部分唯一索引同时兜底「重复申请」）；成功邮件改发**师傅**「收到拜师申请」（含申请人境界 +「游戏内仙务·师徒页签可处理」指引——顺手把 :6528 的 `/yl/apps/mentor/` 字样换掉），申请人回执「申请已提交，等待对方收纳」（toast 串 @886886 从此与行为一致）。
- **新 N1** `POST /api/mentor/decide {apprenticeId, action:'accept'|'decline'}`：
  1) 仅师傅可调；`SELECT … WHERE apprentice_id=? AND mentor_id=? AND status='pending'` 未命中 → 409；
  2) 过期判定：`created_at < now − MENTOR_APPLY_TTL_MS` → 置 declined + 409「申请已过期」；
  3) accept：守卫式单语句 `UPDATE mentorships SET status='active' WHERE id=? AND status='pending' AND (SELECT COUNT(*) … mentor_id=? AND status='active')<3 AND NOT EXISTS(双方 expired 冷却 …)`，changes=0 → 409 逐项诊断（口径抄存量 :6510-6523）；成功 → 复用 :6515-6532 双方邮件（文案改「收纳」语境）；
  4) decline：`UPDATE … SET status='declined' WHERE id=? AND status='pending'` → 邮件告知申请人。
- **新 N2** `POST /api/mentor/cancel`：徒弟撤回自己的 pending（`UPDATE … SET status='declined' WHERE apprentice_id=? AND status='pending'`，changes=0 → 409「无待处理申请」）。撤回/被拒**不进冷却**，可立即再申请（行置 declined 后部分唯一索引即释放）。
- 兼容：存量 active 关系原样；graduate/expire 只认 active（:6546/:6598），pending/declined 行不被误出师/误解除；my 历史 C2 过滤（下表）。

### 3.2 出师

- 条件不变：徒弟境界≥金丹期（`MENTOR_GRAD_REALM_INDEX=2`）。**双向按钮**：师傅在弟子行 [准予出师]（存量）、徒弟在师傅卡 [申请出师]（=自调用 graduate，:6546 已支持，纯 UI 补齐——P5 根治）。
- 进度可见：师傅卡/弟子行渲染「出师进度：当前境界 X 层 → 金丹期」（my 已返回 realmIndex/realmLevel，纯前端算）。
- 奖励闭环（存量保留）：师傅得徒弟拜师以来累计灵石收益（stats_daily 同源 :6556）×30% 邮件 + 7 天 ×1.3 收益增益 + 称号「良师益友」。
- **P1 新增（小）徒弟出师贺礼**：graduate 成功后给徒弟加发一份出师贺礼邮件（灵石 = **`floor(MENTOR_GRAD_GIFT_BASE × realmMultOf(徒弟))`，`MENTOR_GRAD_GIFT_BASE=3000` 已定档**（《数值表-T7T8》T8-8）⇒ 金丹 6,750 / 元婴 10,125 / 化神 15,187 / 合道 22,781 / 长生 34,171，量级 4.6~8.9 分钟时薪），闭环对称。**发放频控（数值批新增，堵刷子）：每徒弟每日限 1 笔**——出师不冷却 ⇒ 理论「出师→再拜→再出师」循环 × mentor:grad 频控 10/min = 67,500 灵石/分无成本注入；graduate 内一条 SELECT（当日该徒弟 `completed` 行数 ≥1 → 贺礼置 0，出师本身不受影响），零新表零迁移。实现 = graduate 端点内 `insertMail(apprenticeId, …, stones)` 一行；**发信失败不回滚出师**（师傅侧 :6577-6581 的回滚只保护大额回馈；徒弟礼小额，失败仅日志，避免扩大回滚面——「先占位→再动账→失败补偿」的补偿面按金额分级）。

### 3.3 传功（★ 本会话纠偏：频控是「每师傅每日 1 次总量」，不是每徒）

- **事实**：`teach_log` 的 UNIQUE 约束是 `(user_id, date)`（:748），即师傅每天只能传功 **1 次**（全体弟子合计）；多弟子时端点要求 `apprenticeId` 参数（:7436），而现客户端从不传 ⇒ 只会传给列表第一位。Y6B 记忆与服务端注释（:7219「传功：师傅每日 1 次」）均为「每日 1 次」口径。
- **设计裁定：保留 1 次/日总量**。理由：①改「每徒每日」需重建 teach_log 约束（SQLite 不能改约束，须建新表拷数据改名），违背「新表 0 张」且收益不成比例；②「每日传功一次、点名一位弟子」语义自洽，仪式感反而更强。改为每徒每日列入 §9 遗留。

>
> - **拜师**：在师徒页搜索师傅名号提出申请，对方收纳后即刻生效。师傅须境界≥筑基期、总等级（境界序×9+层数）比你高 5 级、门下还有空位（最多同时带 3 名弟子）；申请 48 小时内有效，可随时撤回，被婉拒不进冷却、可立刻改投他人。
