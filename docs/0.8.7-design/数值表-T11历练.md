## 2. 审计 B：为什么 0.8.5 的 ÷5 没修好（三重根因）

1. **`By` 的隐藏 ×5 从未被审计到**。0.8.5 定量地图（`yl_eco085_ext.py` :30 表注）写「**不动** 历练战斗 `By` | `…×10` | 300」——审计只追到 `By` 的返回值 `M≈300`，**没有追到结算点 `Q=_?I*5` 的再乘 5**。实际入账 1,500/场（筑基 L1），且战斗线占历练总产出 58%~93%（表4：炼气 L1 战斗 202,025/h vs 事件+lucky 14,360/h）⇒ **用户体感 0.8.5 前后无差别，完全成立**。
2. **第三份过滤器 `_ylk` 漏网**（铁律⑤「改过滤器先数份数」的又一次应验）：0.8.5 E2 正确找到了两份（`_ylfb`/`_ylf`，expect=2 改成 100%），但**抽奖 draw 里还有第三份语义相同的守卫**——90% 折算 + 天价折算额。lottery 事件单次期望 **19,619（炼气）/ 41,991（筑基）/ 66,396（金丹）灵石**（表5 注），这就是「随便历练一次就能获得几千灵石」的最强单点。
3. **生成侧境界门字段失配**：`YLRealmOk(q,v)`（@602859）读 `q.realmRequirement`（fallback `q.minRealm`），而 `WN()` 掉落池装备（@322401）只有 `realm:rl` + `name:"["+rl+"]"+nm` ⇒ 两字段全 undefined ⇒ `return !0` **恒放行**。v26l 设计的「+1 阶 18% / +2 阶 1.5% / ≥+3 阶 0%」对主掉落池从未生效过，一切压力都在下游折算过滤器上。
