### 1.2 超阶掉落的到达概率结构（验算的概率底账）

- `YLRealmOk`（bundle @602859，v26l 装备掉落境界门）：物品等阶 = 玩家+1 → **18%** 放行；+2 → **1.5%**；≥+3 → **0%**。⇒ 战斗/历练掉落路径的超阶装备占比被上游门槛限死在 ~19.5%。

### 1.3 病灶定性（为什么「当前值明显偏高」）

1. **稀有度失明**：普通（掉落占比 ~62~80%）垃圾与仙品珍品同价。一个筑基玩家捡到超阶**普通**金丹武器得 16 灵石——而同事件白档抽奖期望只有 130、矿脉事件均值 160，junk 补偿与正经灵石事件同量级。
2. **顶格无差别**：任何长生装备（含普通）一律 160，是同境界矿脉事件均值（1,678）的 ~10%——一个**无限次**通道的单次补偿达到日常事件的 10%，违背 0.8.5「持续获取通道 ÷5」的既定口径。
3. **桶边界粗**：化神/合道共用 60、炼气~元婴共用 16，等阶梯度断裂。

## 2. T2 新表：超阶物品转换灵石表（等阶 × 稀有度）

### 2.1 设计法则

```
折算灵石 = base[q] × mult[r]        （q=物品等阶序 0..6；r=物品 rarity 序 0..3）
base[q] = [1, 2, 3, 5, 8, 12, 20]   （等阶基数，×~1.6/阶 = 同游戏境界成长系数）
mult[r] = [1, 2.5, 5, 8]             （普通/稀有/传说/仙品；锚抽奖四档中值比 1:3:9:23 的收敛版）
```

- **rarity 取自物品对象 `x.rarity`**（不必解析名字），缺省按「普通」（最保守）；稀有度序与产物 `zc=["普通","稀有","传说","仙品"]`（@667490）同序，但**实现必须自含定义**（不引用压缩符号，跨构建不稳，T6 §4.2 同纪律）。
- **不随玩家境界缩放**（与现行一致，物品内在价值口径）：§3.2 预算验算证明不缩放也不越界。
- `q0`（炼气）行**永不触发**（无更低境界玩家；两份过滤器外层都有 `fe.indexOf(realm)>=0` 守卫），列全为公式完整性。
- 天地之魄进阶物品（`isAdvancedItem`）在过滤器之前放行（`return true` 通道），**不进折算**，本表不影响。

### 2.3 实现形态（给实现批，自含常量、零 minified 引用）

```js
var YLXW_CVT_BASE=[1,2,3,5,8,12,20];              /* 等阶基数 q0..q6 */
var YLXW_CVT_MULT=[1,2.5,5,8];                    /* 普通/稀有/传说/仙品 */
var YLXW_CVT_RAR=["普通","稀有","传说","仙品"];
function YlxwCvtStones(x,q){
  var ri=YLXW_CVT_RAR.indexOf((x&&x.rarity)||"普通"); if(ri<0)ri=0;
  var qq=Math.max(0,Math.min(6,q|0));
  return Math.round(YLXW_CVT_BASE[qq]*YLXW_CVT_MULT[ri]);
}
```

- `(_q>=6?160:_q>=4?60:16)` 2 → **0**；
- `function YlxwCvtStones(` 定义恰 1、调用恰 **2**（两份过滤器各一）；
- `YLXW_CVT_BASE=[1,2,3,5,8,12,20]`、`YLXW_CVT_MULT=[1,2.5,5,8]` 各恰 1；
- 门禁脚本对常量表复算断言：`max=160`、行列单调不减、全整数（脚本侧断言，非 grep）。

## 5. T3 新表：心法 100 级

### 5.1 成长定义（放前面：攻/防/血）

| 属性组 | 每级 | 倍率公式 `mult(L)` | L1 | L50 | **L100（满级）** |
|---|---|---|---|---|---|
| **攻击 / 防御 / 气血** | **+1%** | `1 + 0.01 × L` | ×1.01 | ×1.50 | **×2.00（合计 +100%）** |
| **神识 / 体魄 / 身法**（其余属性） | **+0.2%** | `1 + 0.002 × L` | ×1.002 | ×1.10 | **×1.20（合计 +20%）** |

- 「每级 +1%」按**满级合计 +100%**（=1%×100）取整口径：L=1 即 +1%（学得即 1 级），线性累加到 L100 恰 ×2.00；「其余属性」同理恰 ×1.20 =「满 100 级合计 +20%」。

## 6. T3 验算

1. **倍率**：`1+0.01×100 = 2.00`（攻/防/血满级恰 +100%）；`1+0.002×100 = 1.20`（其余恰 +20%）——与任务口径逐字对齐；脚本断言 L1/L50/L100 三点输出一致。
2. **属性注入上限抽查**：顶配单本 = `art-chaos-primal` 攻 12,942（重规划后，数值重规划案附表 #72）× 2.00 × 1.48 × 1.0（第 1 本递减系数）= **38,308**，较现行满配（×1.48）19,154 增加 ~19,000——相对长生境装备词条量级（attack 基 8×244.14×品级系数 ≈ 千级/件 × 多件）为**月级专精的可感增益**，非破表；且攻/防/血外的四维反而被压到 ×1.776 < 现行 ×2.37（原 expRate 通道不动、其余属性现口径 ×1.48→新 ×1.20×1.48）。全维度满配总量变化 ≈ 主属性 +~50%/本、副属性 -25%/本，由「修炼到 L100」这一长线投入换取，PvE/PvP 对称。
3. **经济沉淀容量**：天品单本满级 2,112,000；28 本天品全满 = **59,136,000 灵石** ≈ 长生时薪口径 **257 天时薪**——为一个数量级健康的终局灵石沉淀口（对照：洗炼单件封顶 40,000/次、茶馆单注封顶 50,000×3/日）。
4. **EV 红线**：修炼是**纯支出**（无产出对价、无随机、无赔率常量），EV≤1 约束不适用；铁律②「加大只动注额次数不动赔率」——本表只新增支出档位，未动任何赔率。
5. **配额核对**：扣灵石 = 负增量，`settleSaveEconV2` 仅钳正增量（数值重规划案 §5.1 机制）；`E2_LUMP_STONE_ALLOWANCE` 等常量**零改动**。expRate 不成长 ⇒ `min(1.25,…)` 封顶与 medEach 余量论证**原样成立**。
6. **数据结构与门禁**（给实现批）：
   - `player.artLevels = {"<artId>": L}`，缺省懒初始化 L1；修炼动作 = 余额守卫（`spiritStones ≥ cost`）→ 扣款 → `artLevels[id]+1`（≤100 封顶）→ 失败无副作用（纯客户端顺序执行，无并发面）。
   - 结算/面板两处同系数（铁律⑤反向应用：v28 心法补丁恰 2 处，`YlxwArtRanked(t).forEach…` 与 `YlxwArtAdd(X,ue.effects,…)`），新倍率作用于 6 项属性、**不触碰 expRate 通道串**。
   - 门禁：`YLXW_ART_LV_MAX=100`、`YLXW_ART_TIER_COST=[300,500,800,1200,2000,3000,5000,8000,12000,20000]` 各恰 1；`artLevels` 懒初始化串恰 1；门禁脚本复算 `cost(99→100)`：天=80,000/玄=20,000；`u.effects.expRate` 消费串仍恰 1（未被缩放波及的证据）。
   - 入口建议：心法面板每本已学心法行加「修炼」钮（费用 tooltip = 服务端同源公式展示，F1 展示=扣费纪律）；批量 ×10 为 P2 可选。
