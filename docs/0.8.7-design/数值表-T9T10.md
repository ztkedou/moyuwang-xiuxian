**不下调的四条理由**：
1. **T9 交付是「途径可视化」不是「降价」**——根因是「锁定等级整行隐藏 + 假满级文案」（设计案 §1.2 缺口①②），不是价格墙本身；降价治不了「看不到途径」。
2. **Pr 表锚区唯一且为既有存量**：下调会改变已升 L5~L9 玩家的沉没成本口径（老玩家无补偿），引入不公平感；且锚区改动会牵动 `Pr` 表相关门禁。
3. **0.8.7 已有足量灵石沉淀口**：T3 心法天品单本满级 2,112,000（28 本 = 5,913.6 万）、T5-C 灵玉阁（纯回收）、T5-D 诛妖符（周 14×时薪）、T10 开垦费 4/5/6 = 300 万。L10=1.5 亿 是「长生日投入 91,915/日 → 1632 天时薪」量级的终局目标，与 T3 满级（23 天/本）分层清晰，不构成短期经济压力。
4. **红线 #11 已从产出侧封顶**（T10 满配日净 ≤ 15 万/日 = 长生时薪 0.65h），无需再用「提高洞府价格」压缩玩家净资产。

`farmSlotsForLevel`：3 基础 + 已达门槛的 4/5/6 号田。曲线（断言：门槛前不越权、门槛后恰开）：

档位设计锚 = T9 既有内容点亮点（L5 传说灵草/聚灵阵、L6 仙品、L9 长生境第二档），与 `Pr` 表的 `maxHerbSlots` 台阶（5/6/8/10/12/15）同向但更缓（灵田扩位是「洞府 meta 成长」的第二个出口，不宜与灵草园槽位同速）。

### 3.3 #5 开垦费 = {4: 200,000, 5: 800,000, 6: 2,000,000}

`FARM_UNLOCK_COST`：2/3 档照录（20,000 / 80,000），4/5/6 定档 **200,000 / 800,000 / 2,000,000**。递进律：`×4, ×2.5, ×4, ×2.5`（2→3 ×4、3→4 ×2.5、4→5 ×4、5→6 ×2.5），全档严格递增。

- 量级校验：三档合计 **3,000,000 灵石** = L10 洞府价（1.5 亿）的 2% ⇒ 扩位是「洞府等级的附属投入」，不构成独立经济压力。
- 定位：**纯灵石回收口**（与催熟费、T3 心法修炼同侧），无对价回流。

### 3.5 #7 虫害/照料 = 30% / −20% / +10%

- 虫害：`farmPestToday(playerId, slot, cropKey, plantedAt, bjDate)` = FNV-1a hash 取模 < 30%，**确定性伪随机**（同输入恒同结果 ⇒ status 与 harvest 各自复算恒一致，零 cron 零落库）。
- 照料（免费）：清当日虫害 + 该田当日收获 **+10%**。
- **正反馈引导成立**（断言已过）：照料收益 `+10%` **>** 不照料期望损失 `30%×20% = 6%` ⇒ 照料是严格占优策略，玩家无「故意不照料」动机；同时照料有「每日每田 1 次」闸门（`farm_daily_care` PK 幂等），不构成无脑重复操作。
- 机制有牙（敏感性，同一最赚作物单田日净）：满配最优 **+20,050** / 仅洞府不照料 **+12,167** / 不照料且虫害命中 **−3,600** / 不照料+虫害+连作 3 茬 **−27,250** —— 照料是「盈利 vs 亏损」的分界线，不是装饰。

### 3.6 #8 高阶作物 ×2

|---|---|---:|---:|---:|---:|---:|---:|---:|
| `lingcao` | 灵草 | 1,000 | 240min (4h) | 800 | 500 | — | 0.800（净亏） | −192 |
| `lingzhi` | 灵芝 | 5,000 | 720min (12h) | 5,000 | 3,000 | — | 1.000 | +2,100 |
| `qianniancan` | 千年参 | 20,000 | 1440min (24h) | 25,000 | 15,000 | — | 1.250 | +10,250 |
| **`taixuguo`** | **太虚果** | **50,000** | **2880min (48h)** | **70,000** | **42,000** | **Lv5** | **1.400** | **+17,350** |
| **`zaohuaqinglian`** | **造化青莲** | **200,000** | **4320min (72h)** | **215,000** | **129,000** | **Lv7** | **1.075** | **+20,050** |

- **三条阶梯律**（断言已过）：① 种子/时长**双单调递增**（1,000→200,000 / 240→4320min）；② **满配日净绝对值**单调递增（−192 → 2,100 → 10,250 → 17,350 → 20,050）——这是「高阶作物值得种」的**唯一正确判据**；③ 洞府门槛 ≤ 对应地块门槛（太虚果 Lv5 = slot4 门槛、造化青莲 Lv7 = slot5 门槛）⇒ 作物门槛与地块门槛同一套档，**不会出现「地块够了但作物种不了」的错位**。
- **★ 设计声明（防误判为缺陷）**：造化青莲**基准净率 1.075 < 千年参 1.250**（种子贵、周期长），但**满配日净 20,050 > 千年参 10,250（×1.96）**——这是刻意的「长周期以绝对日净取胜、不以比率取胜」设计：长周期作物给出更高的**日收益绝对值**（玩家在灵石充足时升级产线），但**不做比率上的无风险套利**（比率仍贴近 1，回本需 3 天时间成本）。与 0.8.5「持续通道不越界」口径一致。
- 修为配比：`exp/stones = 0.625 / 0.6 / 0.6 / 0.6 / 0.6` —— 与既有三作物（500/800=0.625、3000/5000=0.6、15000/25000=0.6）**同序**，无修为通道异常放大。

### 3.7 #9 轮作衰减 = −15% / −30%

`farmStreakDecayOf(streak)`：`streak≥2 → −30%`；`==1 → −15%`；`0 → 0%`。`streak` 由 `spirit_farm` 既有 `harvested=1` 历史行 `ORDER BY id DESC LIMIT 2` 推导，**零新表零加列**；换作物即重置。

- 效果（最赚作物单田日净）：第 1 茬 **+20,050** / 第 2 茬 **+7,042（−64.9%）** / 第 3+ 茬 **−5,965（−129.8%）** —— 衰减叠加在「种子对价 + 3 天时间成本」上，**连作第 3 茬起转亏** ⇒ 机制强迫轮作，玩家不能「一块田种到底躺收」。
- 衰减档严格单调（−30% > −15% > 0），且 `streak=0 → 0%`（重置路径存在且可验证）。

### 3.8 #10 growthSpeedBonus→灵田折算 = ×0.5

`farmMatureAt(now, minutes × (1 − min(0.5, 0.5 × growthSpeedBonus)))`。

| 洞府等级 | growthSpeedBonus | 折算后时长系数 |
|---|---|---|
| L5 | 0.20 | ×0.90 |
| L6 | 0.25 | ×0.875 |
| L7 | 0.30 | ×0.85 |
| L8 | 0.35 | ×0.825 |
| L9 | 0.40 | ×0.80 |
| L10 | 0.50 | **×0.75** |

- **防双吃**：`growthSpeedBonus` 在洞府域已作用于「灵草园生长」；灵田域若 1:1 全额吃进，等于同一属性在两个系统重复兑现。×0.5 折算（上限 25%）把灵田侧的加速压到洞府侧的一半，方向与「灵田是洞府 meta 的从属系统」定位一致。
- 钳位：`min(0.5, ·)` ⇒ 系数下界 ×0.75，**成熟时长永不归零**（不会出现「秒熟」绕过催熟费）。

## 4. 经济红线 #11（核心：绝对值定档 + 复算）

### 4.1 定档与相对式

```
红线 #11（绝对值）: 满配（洞府 L10 六田 + 每日照料）灵田日净收益 ≤ 150,000 灵石/日
相对式（build-plan §2-T10 / §9-5 已裁定）: = T5-C 灵玉阁日上限对价 1,500,000 结算量/日 ÷ 10
```

### 4.2 满配复算（逐项可验，脚本原样输出）

```
最赚作物 = 造化青莲
满配乘区 = (1 + 洞府 L10 +10%) × (1 + 照料 +10%) = 1.10 × 1.10 = 1.21
满配毛额 = floor(215,000 × 1.21) = 260,150 灵石/茬
净收益/茬 = 260,150 − 种子 200,000 = 60,150 灵石（周期 4320min = 3 天）
单田日净 = 60,150 ÷ 3 = 20,050 灵石/日
满配日净 = 20,050 × 6 田 = 120,300 灵石/日     ≤  150,000  ✅  余量 19.8%
```

**口径说明（为什么这样取就是上界）**：
1. **忽略连作衰减**：满配玩家可轮作（造化青莲 ↔ 太虚果）保持 `streak=0` ⇒ 衰减 = 0。**这是刻意的「松弛上界」**（把衰减约束放开），使红线校验对实现改动单向安全；连作约束下的真实最优见下。
2. **无虫害**：照料既给 +10% 又清虫 ⇒ 照料是占优策略，上界必然含照料、必然无虫害。
3. **不含催熟**：催熟单价 100 > 全作物最大每分钟净收益 13.92 ⇒ 催熟恒为回收口，**不抬高上界**（§3.4 结构性断言）。
4. **6 田全开 = 洞府 L10**（slot4/5/6 需 L5/L7/L9）⇒ 「满配」与「洞府 L10」等价，无需再叠加其它前置。
5. **单作物上界**：造化青莲日净（20,050）> 太虚果（17,350）> 千年参（10,250）> 灵芝（2,100）> 灵草（−192）⇒ 松弛上界 = 6 田全种造化青莲。

**连作约束下的真实最优（更强结论）**：`streak` 强制同田不可连种同作物，故「6 田全种造化青莲」不可持续；最优可持续策略 = 每田 **造化青莲（3 天，净 60,150）+ 太虚果（2 天，净 34,700）交替**（`streak` 恒 0）：

```
5 天周期：净 60,150 + 34,700 = 94,850 → 单田 18,970/日 → ×6 田 = 113,820 灵石/日
⇒ 113,820（真实最优） ≤ 120,300（松弛上界） ≤ 150,000（红线）   余量 24.1%
```

⇒ 无论取「松弛上界」还是「连作约束下的真实最优」，**均低于红线**；文档采用 120,300 作为门禁比较值（更保守、且与 `srv_patch_t10_farm.py` 头注释逐字一致）。

### 4.3 量级对照（红线定得住的理由）

| 对照项 | 数值 | 满配灵田占比 |
|---|---:|---:|
| 红线（T5-C 对价 ÷10） | 150,000 /日 | 100% |
| **满配灵田日净（松弛上界，实测）** | **120,300 /日** | **80.2%** |
| 满配灵田日净（连作约束下真实最优） | 113,820 /日 | 75.9% |
| 长生境时薪（`rainHourlyStones`） | 229,788 /h | 0.52 小时挂机收入 |
| 长生境全天挂机（24h） | 5,514,912 /日 | **2.2%** |
| T5-C 灵玉阁日上限对价 | 1,500,000 结算量/日 | 8.0% |

- 定位判读：满配灵田（**最顶配玩家、全部田位、全部加成、无损耗**）的日净 ≈ **0.52 小时挂机收入**、≈ **长生时薪的 2.2%/日**——远不足以成为主收入通道，符合 0.8.5「持续获取通道不得越界」的既定口径。
- 相对式余量 19.8% 提供了缓冲：即使未来放宽某一条（例如 #3 加成提到 +1.5%/级 → L10 +15%，满配日净 ≈ 6 田 × floor(215000×1.15×1.10)/3 = 6 × 21,966 ≈ 131,800，仍 ≤15 万），红线不立即被击穿，但**调参必须回跑 `tools/_t9t10_calc.py`**（§7.2 纪律）。

### 4.4 敏感性（机制约束力，非装饰）

| 情形（同一最赚作物） | 单田日净 | ×6 田 |
|---|---:|---:|
| **满配最优（照料 ✓）** | **+20,050** | **+120,300** |
| 仅洞府加成（不照料） | +12,167 | +73,000 |
| 不照料 + 虫害命中 | −3,600 | −21,600 |
| 不照料 + 虫害 + 连作 3 茬 | −27,250 | −163,500 |
| 零洞府零照料（0.8.6 口径，仅新作物） | +5,000 | +30,000 |

⇒ 灵田是**有管理成本的生产循环**：照料/轮作是盈利前提，放任即亏。红线封顶的是「理想操作」上界，实际收益只会更低。

### 4.5 净值视角（可选参考）

满配 6 田种造化青莲，**种子流水** = 200,000 × 6 ÷ 3 = **400,000 灵石/日**，净 120,300 ⇒ **净收益率 30.1%/轮转**（= 满配净率 1.301 − 1）。玩家需具备 40 万/日 的种子周转能力才能吃满，这本身是 L10 洞府玩家的量级（长生时薪 22.98 万/h）。

## 8. 假设与未决（如实列出）

1. **本批为数值定档交付，未跑 dryrun/sandbox（无改码）**；全部结论为「读常量 + 复算」的静态结论。E13/E14 的在线数值断言由实现批在重建基线产物上执行（build-plan §7 归属：`_e2e_087_master.py`）。

3. **灵草（lingcao）满配仍净亏（净率 0.968）** —— 这是 0.8.6 现值 0.80 的延续，**判定为设计内 loss-leader**（低门槛、4h 快循环、新玩家入门作物，产出附赠 500 修为）。本批不改其 stones/seed（改了会动 0.8.6 既有门禁「三作物数值未动」）。若产品侧要求「满配下灵草也盈利」，最小改动 = 把 `stones: 800` 提到 ≥ 826（1.25×0.968 门槛），但那会击穿基线门禁，需走独立数值批。
4. **造化青莲基准净率 1.075 低于千年参 1.25** —— 刻意设计（§3.6 声明），判据是「日净绝对值」而非「比率」；若产品侧坚持「高阶作物比率必须更高」，唯一旋钮 = 上调 `zaohuaqinglian.stones`（215,000 → ≥ 250,000），但**会同时抬高红线**（6 田日净 = (floor(250000×1.21)−200000)/3×6 ≈ 205,700 > 150,000，**击穿红线**）⇒ 不建议，或须同步下调 #3 加成/收紧 #4 门槛。**当前定档与红线自洽，无冲突**。
5. **催熟实际使用率未实测**：§3.4 是结构性断言（单价 > 每分钟净收益），不依赖使用率；e2e 若观测到「催熟被大量使用」也只会增加灵石回收，方向安全。
