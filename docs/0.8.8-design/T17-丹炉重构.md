## 0. ★ 一页结论（先给判断）

### 0.1 现状真相：**游戏里同时存在三套「炼丹」，互相不通信 —— 这就是用户要「彻底重构」的根因**

分诊文档只统计了中文串，本会话按**英文键 + 函数体**复查，实测结果如下：

| 系统 | 入口 | 实现位置（本会话实测） | 规则 |
|---|---|---|---|
| **A · 丹房（客户端即时炼丹）** | 主界面快捷按钮「**炼丹 · 炼器**」（`children:"炼丹 · 炼器"` 副标题「神丹 · 神兵」@785025）→ 弹窗 `L4`（标题 `丹房`/`炼器坊`，`size:"4xl" height:"2xl"` @1191869） | `handleCraft` @731230 起（~1.9k 字符完整引擎） | **20 丹方 + 灵草材料 + 成功率 + 纯度 + 造诣 1~9 层**；即时（800ms 动画）出丹，入背包 |
| **B · 仙务·丹炉（服务端延时炼丹）** | 仙务枢纽 `alchemy` 页签 → `YlxwTAlchemy` @861166；注册 `YLXW_COMP.alchemy` @935308 | 服务端 `/api/alchemy/list·start·claim` @5772-5896 | **3 炉位 + 3 丹方 + 纯灵石 + 100% 成功 + 化灵返还灵石**；丹药**不是实体** |

### 0.3 重构定位（★ 需用户拍板的核心取舍）

> **定位：丹炉 = 丹道「挂机线」；丹房 = 丹道「急用线」。两者同源同价（同丹方/同材料/同成功率/同造诣），差异只在「离线推进 + 3 炉并行 + 火候可调」。**

理由：
1. **丹房（A）已经是一个完整好用的系统**（20 丹方、成功率、纯度、造诣、失败分支）——推倒它等于把最好的部分丢掉。
2. **丹炉（B）的病灶是「它自己另立了一套规则」**：灵石换灵石、无材料、无造诣、无随机。**把它改造成 A 的挂机版，是最小改动、最大收益的路径**。
3. **A 与 B 的差异必须"有理由"**，否则玩家会问「为什么两个炼丹」。理由 = **离线推进 + 并行 + 火候**（挂机的天然优势）。
4. **丹药必须成为实体**（消除 P2）：服务端已有 `updatePlayerSave(userId, fn)`（:1208）且已在 `POST /api/alchemy/start` 里用它扣灵石，GM 路径也用它写 `player.inventory`（:2547-2553 / :2643-2649）⇒ **「服务端无法入包」这个 0.8.7 的判断是错的，可以修**。

**取舍点（报用户拍板）**：
- **A. 是否保留丹房弹窗？** 本文默认**保留**（丹房=急用、丹炉=挂机）；备选：丹房炼丹并入丹炉、弹窗只留炼器。
- **B. 丹药能否出售换灵石？** 本文默认**不能**（丹炉是纯灵石回收口，丹药价值在修为/属性）；备选：加「丹药出售」但售价 < 成本（§5.6 给表）。
- **C. 火候是否新增？** 本文默认**新增**（文火/中火/武火，丹炉专属）；备选：不做火候，丹炉只做并行+离线。
- **D. 丹炉是否保留「化灵返灵石」？** 本文默认**删除**（这是无风险灵石复制，且量级无意义）；备选：保留但降到 1.0（不亏不赚）。

## 2. 统一设计决策（十条）

| # | 决策 | 理由 |
|---|---|---|
| D1 | **丹炉 = 丹房规则的「服务端权威挂机版」**：同丹方表、同材料、同灵石成本、同成功率公式、同纯度公式、同造诣阶梯 | 消除「两套炼丹」的认知分裂（P3）；A 的规则已被玩家理解 |
| D2 | **丹炉产出「丹药实体」入背包**，走 `updatePlayerSave` 写 `player.inventory` | 根治 P2（炼丹拿不到丹）；服务端已有该原语（:1208/:2547/:2643） |
| D3 | **删除 `ALCHEMY_YIELD_RATE` 化灵返灵石** | 消除无风险灵石复制（P5/P6）；量级无意义（3.92 分钟时薪/小时） |
| D4 | **新增「火候」三档**（文火/中火/武火），仅丹炉可用 | 给丹炉**专属策略维度**（时长↔成功率↔纯度），使「为什么用丹炉」有答案 |
| D5 | **丹炉离线推进**：`matureAt` 基于绝对时间戳，登录即结算 | 挂机线的天然优势，丹房不具备 |
| D6 | **造诣（`alchemyLevel`/`alchemyProficiency`）改为「服务端权威 + 客户端同步」**：落新表 `alchemy_profile`，随存档双写 | 根治 P7；避免与客户端存档互相覆盖（§6.5 竞态方案） |
| D7 | **丹方按造诣等级解锁**（§5.5），丹房/丹炉共用 | 给造诣成长一个**可见的回报**；现状 20 方一开始全开 = 无梯度 |
| D8 | **丹房（弹窗）保留不动**（含炼器坊） | 用户 item 18 说明弹窗在用；A 是完好的，本批只修布局（§7） |
| D9 | **凝元丹垫刀联动保留**：凝元丹出炉/入包时仍 `pill_stash +1` | 不动存量渡劫机制（C 系统） |
| D10 | **新常量集中在一个 `[alchemycore]` 区**（服务端常量块 + 客户端同源镜像） | 对齐 T8 `[mentorcore]` / T16 `[arenacore]` 纪律，调参只动一处 |

### 3.2 核心循环

```
[材料] 洞府种植灵草（20 种，Lv1/3/5/6 门槛）/ 历练掉妖丹 / 炼器坊买高阶妖丹
   ↓
[投料] 丹炉选丹方（按造诣解锁）→ 校验材料 + 灵石 → 选火候（文/中/武）→ 占炉
   ↓
[等待] 丹火时长（按品阶 × 火候，10min ~ 960min）——**离线也在推进**
   ↓
[出炉] 服务端判定：
        成功 → 得丹药（品质 = 纯度档，效果 × 纯度倍率）→ 写入背包
        失败 → 得「废丹」（hp −50）＋ 少量熟练度
        炸炉（失败中的 20%）→ 扣 maxHp×10% 气血 ＋ 零熟练度
   ↓
[丹药] 服用（修为 / 永久属性 / 寿命）／ 垫刀（凝元丹 → 天劫 +3%/颗）
   ↓
[成长] 造诣 +熟练度（炉炼 ×1.2）→ 成功率↑ 纯度↑ → 解锁高阶丹方
```

### 3.3 炉位

- **3 炉位**（`ALCHEMY_SLOTS = 3`，**不动**）。每炉位独立 `UNIQUE(player_id, slot)`。
- 3 炉位**可并行不同丹方 + 不同火候**（重构后新增能力）。
- 单炉位在炼时不可重复开炉（存量守卫，不动）。

### 3.4 火候（★ 新增，丹炉专属）

| 火候 | 时长倍率 | 成功率修正 | 纯度修正 | 熟练度倍率 | 解锁 |
|---|---|---|---|---|---|
| **文火**（慢） | ×2.0 | **+10%** | **+8** | ×1.0 | 造诣 **Lv3** |
| **中火**（默认） | ×1.0 | 0 | 0 | ×1.0 | Lv1 |
| **武火**（快） | ×0.5 | **−12%** | **−6** | ×0.8 | 造诣 **Lv5** |

> 设计意图：**文火 = 稳妥求品质（慢一倍换 +10% 成功率 +8 纯度）；武火 = 求速度（快一倍但 −12% 成功率、−6 纯度、熟练度 −20%）**。三档互有取舍，无绝对最优。

### 3.5 成功率

```
P = clamp(0.05, 0.98, Base[rarity] + (Lv−1)×0.05 + luck×0.001 + Fire.rateAdd)
Base = { 普通 0.95, 稀有 0.80, 传说 0.60, 仙品 0.30 }        # 与客户端 Jb 同源
```
- `Lv` = 丹道造诣（1~9），`luck` = 玩家气运属性。
- 上限 **0.98**（与客户端同，永不 100%）。

### 3.6 纯度与品质

```
Q = clamp(60, 100, floor(60 + rand(0,20) + (Lv−1)×2 + luck×0.05 + Fire.purityAdd))
```
| 纯度 Q | 品质档 | `effect` 倍率 | `permanentEffect` 倍率 |
|---|---|---|---|
| 100 | **完美** | ×2.500 | ×1.500 |
| 95 ~ 99 | **极品** | ×2.375 | ×1.438 |
| 85 ~ 94 | **上品** | ×2.125 | ×1.313 |
| 70 ~ 84 | **中品** | ×1.750 | ×1.125 |
| 60 ~ 69 | **下品** | ×1.500 | ×1.000 |

> 倍率公式（与客户端 `DN` 逐字同源）：
> `effMult = 1.5 + (Q−60)×0.025`；`permMult = 1.0 + (Q−60)×0.0125`
> 效果应用用**递归 floor 乘法**（`gm`，与客户端同），保证整数属性不出现浮点尾巴。

### 3.7 失败分支（与客户端同源）

| 分支 | 触发 | 结果 |
|---|---|---|
| 炸炉 | 失败后 `rand < 0.2` | `hp = max(1, hp − floor(maxHp×0.1))`；**无产出**；熟练度 **+0** |
| 废丹 | 失败后 `rand ≥ 0.2` | 得「废丹」×1（`hp:−50`）；熟练度 `+max(1, floor(ug/5))` |

### 3.8 造诣成长

```
升级门槛 pm = [0, 100, 300, 800, 2000, 5000, 12000, 30000, 80000]     # Lv1→Lv9
熟练度增益：
  成功 = floor(ProfGain[rarity] × Fire.profMult × 1.2)                # ★ 1.2 = 炉炼加成
  失败 = max(1, floor(ProfGain[rarity] / 5))
  炸炉 = 0
ProfGain = { 普通 10, 稀有 30, 传说 100, 仙品 500 }
```
- `Lv` 上限 **9**；`Lv1→9` 累计熟练度 **130,200**（§5.4 复算）。
- **炉炼熟练度 ×1.2**：这是「为什么用丹炉」的第三个答案（除离线、并行外，成长快 20%）。

### 6.3 核心结算函数（★ 抽公共，避免三处判定不一致）

```
alchemyResolve({ recipeKey, fire, level, luck, seed }) -> { ok, purity, tier, effMult, permMult, profGain, hpLoss }
  ├─ 用 seed 派生确定性随机（mulberry32/xorshift），同一 seed 恒同结果（防客户端重放挑结果）
  ├─ P = clamp(0.05, 0.98, Base[rarity] + (level-1)*0.05 + luck*0.001 + Fire.rateAdd)
  ├─ ok = rand01() < P
  ├─ 若 ok：Q = clamp(60,100, floor(60 + rand01()*20 + (level-1)*2 + luck*0.05 + Fire.purityAdd))
  ├─ 若不 ok：rand01() < 0.2 ? 炸炉 : 废丹
  └─ profGain = ok ? floor(ug[rarity]*Fire.profMult*12/10) : (废丹 ? max(1, floor(ug[rarity]/5)) : 0)
```
- **丹房（客户端）与本函数共用同一公式**（客户端 `handleCraft` 不改公式，只补「火候=中火」默认值）。
- **数值常量单一来源**：服务端 `[alchemycore]` 常量块；客户端同源镜像（D10）。

### 6.4 丹药入包的原子性（★ 核心风险点）

`POST /api/alchemy/claim` 的成功路径必须**全或无**（对齐 `mailClaimCore` / `alchemy start` 的补偿式纪律）：

```
1. 守卫式 DELETE alchemy 行（原子防双领）—— 失败 → 409「该炉已领取」
2. 判定 alchemyResolve(...)
3. updatePlayerSave(userId, sd => {
     若 ok:  sd.player.inventory = vsStack(sd.player.inventory, {name, type:'丹药', rarity, purity, effect, permanentEffect}, 1)
             （或按品质改名为「上品破境丹」并堆叠，见 §9 拍板点 H）
     若废丹: sd.player.inventory = vsStack(..., 废丹, 1)
     若炸炉: sd.player.hp = Math.max(1, hp - floor(maxHp*0.1))
     sd.player.alchemyLevel/alchemyProficiency 同步（或只写 DB，见 D6）
   })
4. 若第 3 步失败 → 回滚第 1 步（INSERT 回炉行，`INSERT ... VALUES` 必不冲突）→ 500「发奖失败，请重试」
5. 成功 → upsert alchemy_profile（level/proficiency/crafts/success）+ INSERT alchemy_log
6. 凝元丹特例：pill_stash +1（存量 upsert，失败只记日志不阻塞）
7. 活跃度埋点 bumpAlchemyQuest(userId)（fire-and-forget）
8. 掉玉挂点：改为「按丹药稀有度」而非灵石（§9 拍板点 E）
```

### 6.5 ★ 造诣权威性与竞态（D6 落地）

**问题**：`alchemyLevel`/`alchemyProficiency` 在客户端存档里（客户端权威），丹炉若在服务端改它，客户端下次上传存档会覆盖。

**方案（三选一，本文建议 A）**：
- **A（推荐）**：造诣**权威迁到服务端 `alchemy_profile`**；客户端丹房的 `handleCraft` 改为**调服务端接口**（或至少在上传存档时**忽略**客户端的 `alchemyLevel`，由服务端下发覆盖）。`updatePlayerSave` 已设 `gm_revision++` 促客户端拉新档，机制现成。
- **B（保守）**：造诣仍客户端权威；丹炉只**读**存档里的 `alchemyLevel` 用于判定，熟练度增量**回写存档**（`updatePlayerSave` 改 `sd.player.alchemyLevel/alchemyProficiency`）。风险：与客户端并发炼丹时可能丢增量（概率低）。
- **C（最保守）**：丹炉造诣**独立**（新表），与丹房造诣**不共享**——**不推荐**（就是现状的 P3 病根）。

## 8. ★ 玩法说明（玩家可见文案，面板「玩法说明」折叠块全文）

> **丹炉是修士炼丹的地方。** 采灵草、配妖丹、控火候，一炉好丹能让你修为暴涨、脱胎换骨。
>
> **【两种炼丹，随你选】**
> - **丹房**（主界面「炼丹 · 炼器」）：**立刻开炉、立刻得丹**。急用丹药、手头材料够了就来这儿。
> - **丹炉**（本页）：**投入材料后等丹火慢慢烧**，但**离线也在炼**，而且**三个炉位能同时开**、**火候能自己调**、**丹道造诣涨得快 20%**。不着急的时候，把材料丢进丹炉最划算。
> - 两边**丹方、材料、灵石消耗、成功率、造诣完全一样**，只是快慢不同。
>
> **【怎么炼】**
> 1. 在**洞府**种下灵草（洞府等级越高，能种的灵草越珍贵），成熟后自动收进背包；妖兽内丹从**历练**里打，高阶妖丹能在**炼器坊**买。
> 2. 在丹炉选一个**丹方** → 选**火候** → 选一个**空炉位** → 点「开炉」。
> 3. 丹火时辰到了（**离线的也算**）→ 点「出炉」拿丹。
>
> **【火候有讲究】**
> | 火候 | 时间 | 成功率 | 丹药品相 |
> |---|---|---|---|
> | **文火**（慢） | 慢一倍 | **+10%** | **+8** |
> | **中火**（默认） | 标准 | — | — |
> | **武火**（快） | 快一倍 | **−12%** | **−6** |
> 求稳求品相用文火，赶时间用武火。文火需造诣 **3 层**、武火需 **5 层**。
>
> **【丹成与丹败】**
> - **成丹**：丹药分 **下品 / 中品 / 上品 / 极品 / 完美** 五档，品相越高，药效越强（**完美丹药的效果是下品的 1.67 倍，永久加成是 1.5 倍**）。
> - **废丹**：火候未到，只得一颗「废丹」（服用会伤气血），但也涨一点造诣。
> - **炸炉**：丹炉炸开，你会**受到自身气血一成的反噬**，这一炉白费。
>
> **【丹道造诣】**
> - 每炼一炉都涨**熟练度**，攒满就**升一层**（最高 **9 层**）。造诣越高，**成功率越高**（每层 +5%）、**丹药品相越好**。
> - 造诣还能**解锁更高级的丹方**：仙品大丹要 **9 层造诣**才炼得动。
> - 在丹炉炼丹，熟练度比丹房**多 20%**。
>
> **【丹药有什么用】**
> - **涨修为**（如聚气丹、破境丹、九转金丹）
> - **永久加属性**（如凝神丹加神识、强体丹加体魄、龙血丹加气血）
> - **延长寿命**（如延寿丹、长生丹、不死仙丹）
> - **洗炼灵根**（如洗灵丹、五行灵丹、天灵根丹）
> - **凝元丹**：出炉会直接进你的**丹囊**，渡劫时每颗能**+3% 成功率**（可一次垫多颗）。
>
> **小贴士**：丹炉不抢你的挂机时间——**离线它照样炼**。早上开三炉，晚上回来收丹，是最省事的用法。

（数值变动时只需改此块与 §5 常量区，两处同批装配；服务端 `/api/alchemy/list` 下发常量后，文案优先动态拼接。）
