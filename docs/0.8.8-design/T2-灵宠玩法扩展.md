## 0. 一页结论

| 问题 | 诊断 | 本案核心 |
|---|---|---|
| 「宠物有具体作用吗？」 | **有系统、没闭环**。游戏里同时存在**两套互不连通的灵宠**（服务端 Y18「妖灵」/ 客户端「灵宠系统」），且服务端那套的**战斗加成根本没接进客户端**（srv 源码自注：「实际战斗加成待客户端接入」）——玩家在「仙务·妖灵」里喂养/嬉戏，喂出来的 `hunger/level/bond` **对战斗力零影响**，所以「看不出作用」 | **三线合一**：把「妖灵（喂养/嬉戏）」与「灵宠（进化/秘径/远征）」打通成**同一只宠**；宠物产出**主人属性加成（出战/助战）**，并把这些加成**显示在角色面板**上 |

### 1.4 根因诊断（回答用户那句「宠物有什么用」）

1. **两套灵宠互不相通**：仙务·妖灵（服务端 `pets` 表，每玩家 1 只，喂 `hunger`）与灵宠系统（客户端 `player.pets`，可多只，喂 `exp/affection`）**是两套独立数据**，名字/属性/成长线都不共享。玩家在仙务·妖灵看到的宠，和战斗里出场的宠，**不是同一只**。
2. **服务端妖灵的加成没接线**：`bond/level/rarity` 算出来只进了日志和邮件，**没进任何战斗公式**。
3. **客户端灵宠「参战」但不可见**：`Oy` 确实让宠物打技能，但面板只写「亲密度影响：治疗技能 +X%，普通攻击 +Y 点」——**玩家看不到「我的宠物一共给我加了多少」**，感知不到。
4. **秘径/远征 = 纯资源兑换**：花灵石 → 换材料/修为，与「宠物」本身的养成无强关联（派遣收益只随 `petLevel` 微增）。
5. **没有融合**：用户期待「融合」这条养成线，产物里不存在。

## 2. 玩法扩展设计

### 2.1 总设计：灵宠三线合一

```
                    ┌──────────────── 养成线（融合 / 进化 / 喂养 / 嬉戏）────────────────┐
                    │  品阶 ↑  阶段 ↑  亲密度 ↑  羁绊 ↑                                  │
                    └───────────────┬──────────────────────────────┬──────────────────────┘
                                    ↓                              ↓
             战斗线（出战 / 助战）                        生产线（远征 / 秘径）
        · 1 主战宠 + 2 助战宠 → 主人属性加成        · 派遣 3~4 队 → 灵石/材料/修为
        · 参战技能（既有 Oy 结算）                  · 收益随 品阶/阶段/亲密度 提升
        · 加成在【角色面板】可见 ← 解决「看不出作用」  · 秘径 = 即时高收益（有冷却）
```

**设计原则**（三条硬约束）：
- **P1 可见化**：任何加成必须在角色面板 / 灵宠面板给出**具体数字**（延续 0.8.7 item 1「称号展示加成数值」同一纪律）。
- **P2 不新增权威源**：灵宠属性仍以客户端存档 `player.pets` 为唯一事实源（战斗在客户端结算，先例：`Oy`）；服务端 `pets` 表只承载「妖灵」养成，**通过一次合并动作把服务端妖灵结算进客户端灵宠**（§2.7）。
- **P3 不做赔率**：融合成功率是**确定性成长消耗**（非赌博型随机收益），失败保底必给（§2.4），不构成「赔率常量」（与 T9T10 红线口径一致）。

### 2.2 出战 / 助战机制

| 栏位 | 数量 | 解锁条件 | 加成转化率 |
|---|---|---|---|
| **主战宠** | 1 | 默认（沿用既有 `activePetId`） | **50%** |
| **助战宠** | 2 | 助战位 1：洞府 Lv3；助战位 2：洞府 Lv6（复用 T9 洞府等级档） | **15%** / 只 |

- **转化率**是「宠物属性 → 主人属性」的基准比例，再乘 §2.3 的品阶/阶段/亲密度系数。
- 同一只宠**不可同时**占主战与助战；助战宠不可重复。
- **远征中的宠不可出战**（`petExpeditions` 中 `status !== "claimed"` 的宠占用，避免「一宠多吃」）。

### 2.3 属性换算（宠物 → 主人）

```
主人加成(属性) = floor( 宠物属性 × 转化率 × K品阶 × K阶段 × (1 + 亲密度/200) )
  K品阶 = { 普通 1.0, 稀有 1.2, 传说 1.6, 仙品 2.2 }     ← 与 §3 秘径同一套品阶系数
  K阶段 = { 幼年期 1.0, 成熟期 1.2, 完全体 1.5 }          ← 与 §3 秘径同一套阶段系数
  转化率 = 主战 0.50 / 助战 0.15
```

- **转化属性范围**：`attack / defense / maxHp / speed`（宠物 `baseStats` 的四个键，全部已有）。
- **百分比属性**（新增，来自 §2.5 融合与稀有养成）：亲密度每满 **25 点**额外给主人 **暴击率 +0.5%、闪避率 +0.4%**（上限：亲密度 100 → 暴击 +2% / 闪避 +1.6%）。
- **换算示例**（可手算核对）：

| 场景 | 计算 | 主人获得 |
|---|---|---|
| 仙品「凤凰」完全体、亲密度 100、主战 | 攻击 `200 × 0.50 × 2.2 × 1.5 × (1+0.5)` | **攻击 +495** |
| 同上，气血 | `2500 × 0.50 × 2.2 × 1.5 × 1.5` | **气血 +6,187** |
| 稀有「雷虎」幼年、亲密度 50、助战 | 攻击 `100 × 0.15 × 1.2 × 1.0 × 1.25` | **攻击 +22** |
| 普通「灵狐」幼年、亲密度 50、助战 | 速度 `30 × 0.15 × 1.0 × 1.0 × 1.25` | **速度 +5** |

> 量级校验：仙品主战满配给「攻击 +495 / 气血 +6,187」。对照既有体系——T3 心法天品单本满级消耗 211.2 万灵石、称号/丹药单件给几十~上千点。**灵宠是「长线养成的大额加成」，与洞府/心法同层，不越界**。

### 2.4 融合（★ 新增玩法）

**入口**：灵宠系统弹窗新增「融合」页签（与「我的灵宠」并列）。

**规则**：

```
融合 = 主宠（保留）+ 副宠（消耗）+ 融合费（灵石）
融合费 = 3000 × K品阶(主宠) × (1 + 副宠品阶序号)        ← 品阶序号：普0/稀1/传2/仙3
```

| 情形 | 成功率 | 说明 |
|---|---|---|
| 副宠品阶 **<** 主宠 | `70% + 15% × 品阶差`（上限 100%） | 吞低阶，稳 |
| 副宠品阶 **=** 主宠 | **70%** | 基准 |
| 副宠品阶 **>** 主宠 | `70% − 20% × 品阶差`（下限 20%） | 越级融合，高风险 |

**成功结果**：

| 继承项 | 规则 |
|---|---|
| 品阶 | 主宠品阶不变；若副宠品阶更高，额外 `25% × 品阶差` 概率 **升 1 阶**（上限仙品） |
| 等级 | `max(主宠等级, 副宠等级)` |
| 进化阶段 | 主宠阶段不变；若主宠阶段 < 2 且副宠阶段 ≥ 主宠阶段，`30%` 概率 **+1 阶段** |
| 亲密度 | `max(两只亲密度)` |
| 技能 | 主宠技能 + 副宠**独有技能**（按顺序补，上限 6 个） |
| 物种 | 保持主宠物种（不混种，避免 23×23 组合爆炸） |

**失败结果**：副宠消失，主宠**不变**（不掉级、不掉阶段）；**保底**：同一主宠连续失败 3 次后，第 4 次**必成功**（保底计数落存档 `pet.fusePity`，成功即清零）。

> **为什么这样设计**：融合是「把多余宠变现成主宠成长」的**确定性出口**，解决「抽到重复宠只能放生换灵石」的浪费感；保底保证不构成赌博（P3）。

### 2.5 成长路线（完整链路）

```
抽奖/探索 → 获得幼年宠（stage0，品阶随机）
   ↓ 喂养（既有：气血/物品/修为三选一）→ 等级↑ 亲密度↑
   ↓ 进化（既有：level 门槛 + 材料）→ stage1「成熟期」→ stage2「完全体」（领悟 stageSkills）
   ↓ 融合（新增）→ 品阶↑ / 阶段↑ / 继承技能
   ↓ 出战/助战（新增）→ 主人属性加成（角色面板可见）
   ↓ 远征/秘径（既有 + 收益随品阶阶段提升）→ 灵石/材料/修为
```

**关键改动**：远征/秘径收益从「只随 `petLevel` 微增」改为 **也随品阶与阶段提升**（§2.6），让「养成」直接反哺「生产」，形成正循环。

### 2.6 远征 / 秘径收益与宠物品阶挂钩

| 收益项 | 现状 | 扩展后 |
|---|---|---|
| 远征灵石 | `base + rand + petLevel×系数` | 再乘 `1 + 0.15 × 品阶序号 + 0.20 × 阶段`（普0/稀1/传2/仙3）→ 仙品完全体 = **×1.85** |
| 远征修为 | 同上 | 同上系数 |
| 远征材料掉落 | 固定概率 | 品阶 ≥ 传说 时**额外一次稀有材料 roll**（概率 `10% + 5%×品阶序号`） |
| 秘径产出 | 物品 + 经验 + 亲密度 | 同远征系数；仙品完全体额外 **1 次稀有材料 roll** |

### 2.7 两套系统打通（★ 本项最关键的技术设计）

**问题**：服务端 `pets`（妖灵）与客户端 `player.pets`（灵宠）是两套数据。

**方案（推荐，分两步，0.8.9 可落）**：

- **步骤 1（低风险，先做）**：**「妖灵归位」**——仙务·妖灵面板新增「接入灵宠」按钮：把服务端妖灵按 `rarity` 映射为一个**客户端灵宠**（凡→随机普通种、灵→随机稀有/传说种、仙→随机仙品种），`hunger/100 → level`、`bond → 亲密度换算`（`亲密度 = min(100, floor(bond/2))`），写入 `player.pets` 并设为 `activePetId`；服务端侧 `pets` 行标记 `merged=1`（保留不删，幂等）。
  - **好处**：不破坏任何既有服务端逻辑；玩家「喂养的妖灵」**真的变成**能出战的那只宠；喂养/嬉戏的价值立刻可感知。
  - **代价**：一次性动作，不做双向同步（避免双写冲突）。
- **步骤 2（0.9.x，可选）**：把服务端妖灵改为「客户端灵宠的服务端镜像」——`POST /api/save` 时把 `player.pets` 的主战宠摘要回写 `pets` 表，伴生页 `/yl/apps/pet/` 直接展示主战宠。**本期不做**（跨批改动，需动存档协议）。

> **红线**：步骤 1 只**新增**一个客户端动作 + 一个服务端 `merged` 标记列（`ALTER TABLE pets ADD COLUMN merged INTEGER DEFAULT 0`），**不改任何既有端点语义**。

## 3. 秘径消耗（item 2 的硬指标）

> ★ **2026-09-29 用户拍板（T2-Q1）**：**只改「灵宠面板 · 灵兽秘径」这一条**；洞府「灵兽远征」派遣**保持原样、一行不动**。用户原话：「两个是独立两个功能，远征没有问题，要改的是灵宠面板的内容，现在消耗有点太高了，重新规划一下消耗，基础改为 10000 灵石起，气血和修为也调低一点，整体幅度不要太大，这个消耗多少根据品阶为主，亲密度影响不大。」
> ⇒ 本节取代原「7500 基础 / 两处同套用 / 范围 3.3×」方案。

### 3.0 靶点确认（★ 先查清「到底改哪条」）

用户说的「灵宠面板的秘径」= **客户端 `handlePetExpedition`**（灵宠面板 `vM` 上的「秘径」按钮），**该动作现行消耗同时包含三项**（bundle @1554477 实测）：

```
灵石 = floor(30000 + max(0, 境界序号)×45000 + evolutionStage×90000)      ← 例：金丹期(序号2)·幼年 = 120,000
气血 = max(200, floor(maxHp  × (0.18 + evolutionStage×0.07)))           ← 例：maxHp 625 → 200（触底）
修为 = max(100, floor(maxExp × (0.008 + evolutionStage×0.004)))         ← 例：maxExp 1,521,000 → 12,168
```

⇒ **三项都要调**（用户「气血和修为也调低一点」= 这两项**现行就存在**，不是新加）。**洞府「灵兽远征」`YlxwExpStart`（固定 20,000）不在本次范围内。**

### 3.1 新公式与系数

```
秘径消耗(灵石) = round100( 10000 × P品阶 × P阶段 × P亲密度 )

P品阶 = { 普通 1.00, 稀有 1.20, 传说 1.40, 仙品 1.60 }     ← 主因子（跨度 1.6×，主导）
P阶段 = { 幼年期 1.00, 成熟期 1.10, 完全体 1.25 }            ← 次因子（跨度 1.25×）
P亲密度 = 1 + 亲密度 / 2000                                 ← 弱因子（亲密度 0~100 → ×1.00~×1.05，影响 ≤5%）
round100 = 取整到百位（四舍五入，≥50 进）
```

> **为什么与 §2.3 的 `K品阶/K阶段` 不同**：§2.3 是「宠物 → 主人」的**属性加成**，需要拉开品阶差距以体现养成价值（跨度 2.2×）；本节是**消耗**，用户要求「**整体幅度不要太大**」，故另设一套**压缩系数**（跨度 1.6×/1.25×）。两套系数**用途不同、刻意不共用**，实现时勿混。

**套用位置（仅 1 处）**：
- **灵兽秘径**（`handlePetExpedition`）：`floor(30000 + 境界序号×45000 + evolutionStage×90000)` → `round100(10000 × P品阶(pet.rarity) × P阶段(pet.evolutionStage) × (1 + pet.affection/2000))`
- **灵兽远征派遣**（`YlxwExpStart`）：**不动**（维持 `var _expCost = 20000;`）。

### 3.2 完整数值表（阶段 × 品阶 → 灵石）

| 品阶 \ 阶段 | 幼年期（0） | 成熟期（1） | 完全体（2） |
|---|---:|---:|---:|
| **普通** | **10,000** | 11,000 | 12,500 |
| **稀有** | 12,000 | 13,200 | 15,000 |
| **传说** | 14,000 | 15,400 | 17,500 |
| **仙品** | 16,000 | 17,600 | **20,000** |

- **最低档 10,000 = 用户指定「10000 灵石起」**；**最高档 20,000**（仙品完全体）。
- **极差 = 20,000 ÷ 10,000 = 2.0×**（叠加亲密度弱因子 ×1.05 → 上限 21,000，**极差 2.1×**）→ 符合「**整体幅度不要太大**」（原方案 3.3× 已作废）。
- **单调性**：行、列均**严格递增**（可机检）。
- **品阶为主**：品阶跨度 1.6× > 阶段跨度 1.25× > 亲密度跨度 1.05× ⇒ 权重排序 **品阶 ≫ 阶段 ≫ 亲密度**，符合用户「根据品阶为主，亲密度影响不大」。

### 3.3 抽样验证（手算 3 例，Python 复算一致）

| # | 宠 | 计算 | 结果 |
|---|---|---|---|
| 1 | 普通 · 幼年 · 亲密度 0 | `10000 × 1.00 × 1.00 × (1+0/2000) = 10000` → round100 | **10,000** ✅ |
| 2 | 传说 · 成熟 · 亲密度 50 | `10000 × 1.40 = 14000`；`14000 × 1.10 = 15400`；`15400 × 1.025 = 15785` → round100 | **15,800** ✅ |
| 3 | 仙品 · 完全体 · 亲密度 100 | `10000 × 1.60 = 16000`；`16000 × 1.25 = 20000`；`20000 × 1.05 = 21000` → round100 | **21,000** ✅ |

> 表 §3.2 列的是**亲密度 = 0** 的基准值；实际消耗 = 表值 × (1 + 亲密度/2000)。

### 3.4 气血 / 修为消耗（★ 同步下调至现行的 ~50%~62%）

## 4. 玩法说明文案（UI 直接可用）

### 4.1 灵宠系统弹窗 · 顶部说明块

> **灵宠有什么用？**
> · **出战**：把一只灵宠设为「主战宠」，它会**跟随你战斗**（按亲密度/等级/阶段概率释放技能），并**按比例把你的灵宠属性加到你自己身上**（主战 50%、助战 15%）。
> · **助战**：洞府 Lv3 / Lv6 各解锁一个助战位，可再带 2 只灵宠提供加成。
> · **远征**：派遣灵宠外出探险，到点领取灵石、材料与修为——**品阶越高、阶段越高，带回来的越多**。
> · **融合**：把多余的灵宠融合进主宠，提升品阶、阶段与技能；**连续失败 3 次后第 4 次必成功**。

### 4.2 「出战 / 助战」栏位文案

> 主战宠（1 只）：加成转化 **50%**
> 助战位 1（洞府 Lv3 解锁）：加成转化 **15%**
> 助战位 2（洞府 Lv6 解锁）：加成转化 **15%**
> 实际加成 = 宠物属性 × 转化率 × 品阶系数 × 阶段系数 × 亲密度系数

### 4.3 「融合」页签文案

> **融合规则**
> · 主宠保留，副宠消耗，另付融合费。
> · 副宠品阶越低越稳（最高 100%），越高越险（最低 20%）。
> · 成功：等级取高、亲密度取高、继承副宠独有技能；副宠品阶更高时还有机会**提升主宠品阶/阶段**。
> · 失败：副宠消失，主宠不受损。**连续失败 3 次，第 4 次必定成功。**

### 4.4 「秘径」按钮提示文案（模板）

> 灵兽秘径 · 消耗 **{灵石}** 灵石 + {气血} 气血 + {修为} 修为
> （按品阶与阶段计算：普通幼年 10,000 → 仙品完全体 20,000；亲密度越高消耗略高，最多 +5%）
