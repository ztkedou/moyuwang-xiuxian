## 7. ★ 三个高风险必改点（漏任一条 = 功能不可用或静默回归）

### 必改点① · `POST /api/quest/chest` 内的活跃度校验（`:5496`）
- **现状**：`:5494` 直读 `daily_quests` 当日行 → `:5496` `activityFromQuests(rows)` → `:5497` 判定
- **若不改**：新 14 项不落行 ⇒ 活跃度被 legacy 4 键**封顶 100** ⇒ **第 5/6 档（200/260）永不可解锁**，30/60/100 档也算少
- **改法**：改为调用 `collectDailyActivity`；**`chest_*` 占位行与 `:5507` 回滚 DELETE 保留不动**
- **发现者**：c2（c3 消息触发重查）；c3 已独立核实并写入 T16 §3.5.5-1 / R9

### 必改点② · 论剑计分必须带 `status='accepted'`
- `resolved_at` 在 **accept `:8604` 与 decline `:8631` 都会写** ⇒ 不过滤会把"拒绝的战书"算成活跃度
- **发现者**：c3-design

### 必改点③ · Y19 成就的 `daily_quests` 累计口径（**不许破坏**）
- Y19 `quest_1/10/50/200` 靠 `SELECT COUNT(*) FROM daily_quests WHERE done=1 AND quest_key NOT LIKE 'chest_%'`（读点 `:9646` / `:9678`）
- **处理**：`tickDailyQuests`（`:5045`）**原样保留**（只喂 legacy 4 键）⇒ Y19 口径 **4 行/日 byte 级不变**；**14 个新项目刻意不落行**（否则 Y19 从 4/日 涨到 18/日，`quest_200` 从 50 天加速到 ~11 天）
- legacy 4 键计分取 **`max(行值, 读时值)`**
- **发现者**：c3-design
