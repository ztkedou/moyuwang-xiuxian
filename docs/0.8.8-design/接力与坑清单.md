## 一点五、★★ 抗中断工作流设计（为什么掉线不会造成返工）

> 用户问：「免费额度和积分到期限流、切换模型后继续，会不会让做了一半的工作找不回来、
> 完全返工，或者内容接不上导致 bug？」
> 答：**在本项目的结构下不会**，原因是下面三道隔离。这三道是刻意设计的，不是巧合。

### 隔离一：产物 = 磁盘文件 + md5，不依赖任何模型的上下文
任何成员掉线，它的**中间成果都在磁盘上**（`_chainstage/sN.*.ts` 每环都留档）。
新成员不读旧对话，只读磁盘 ⇒ 上下文丢失**不等于**工作丢失。
判定「做到哪了」的唯一依据是 `ls` + `md5sum`，**永远不是**「上一个成员说它做完了」。

### 隔离二：环与环之间是「文件级接力」，不是「内存级接力」
服务端 17 环各自是独立 py 补丁，`--src 上一环产物` 串行。第 N 环做完就落盘 `sN.*.ts`，
第 N+1 环只认那个文件。⇒ **掉线发生在任意两环之间都不产生半成品**：
要么这一环的产物已落盘（接力棒有效），要么没落盘（重跑这一环即可，前面全部成果无损）。
**危险区只有一处：单环执行到一半被切断**——所以纪律是「一环保一环保地做，环内不夹长任务」。
且每个补丁脚本写回前会生成 `.bak-<name>-<时间戳>`（见 `_chainstage/` 里大量 `.bak-*`），
半途被切也能从 bak 恢复，不会把上一环产物改坏。

### 隔离三：契约（门禁）在文档里，不在成员脑子里
`T7-实现批改动清单.md` 的 §2.8 门禁表、`T9-实现批改动清单.md` 同理 —— 写死在 md 里。
换模型/换成员后，新成员照文档重跑门禁即可**独立判定**前一环对不对。
⇒ **接不上内容的情况被门禁挡住**，不会"悄悄错了往下传"。
（反例：本日 T7 §2.8 的 4 处门禁自毁写法，正是因为没有真读产物验证 needle 计数 ⇒ 坑 14。）

### 因此的排班原则（既并行、又抗断）

| 任务类型 | 并行度 | 抗断理由 |
|---|---|---|
| **只读勘察 / 研究** | 随便并行，不限数量 | 不用落盘，掉线零损失，重跑便宜 |
| **独立产物的实现**（各写各的新文件） | 并行，一人一文件 | 各自产物独立，互不覆盖；掉一个不影响别的 |
| **写同一文件 / 同一环** | ⛔ **严格串行，只派一人** | 防半成品互相覆盖 |

**关键判断**：会不会「两个成员改同一个文件」？会 ⇒ 串行；不会 ⇒ 并行。
本项目里 `srv/index_v28.ts` 是**唯一**的串行瓶颈（18 环），其余（客户端各 `yl_*_ext.py`、
文档、GM 后台、各 `srv_patch_*.py` 新环）都可并行。

### 掉线后的标准动作（lead 执行，不猜、不催）
1. `ls` + `md5sum` 核对**它声称的产物到底在不在**（本日已两次抓到「报 completed 但产物没落盘」）
2. 在 ⇒ 接力棒有效，继续派下一环；不在 ⇒ 重新派**同一任务**，提示语里带上「磁盘上有什么、缺什么」
3. **绝不**因为「上一个成员说做完了」就跳过 md5 核对 —— 这是本项目最高频的翻车点

## 三、★★★ 已踩过的坑（**开工先扫一遍，别重踩**）

### 坑 1：needle 是另一个符号的子串
- 例：`YlxwInhInject` ⊂ `YlxwInhInjectRate`（计数被污染）
- 例：`getPath(` 被看成 `getGameDicts(`（误判影响面，已踩 2 次）
- **对策**：门禁计数用**更长的判别串**，或加词边界；报"调用点"前用精确 `grep -n "名字("` 复核

### 坑 2：注入块中文必须转义，needle 必须写转义形态
- `zh()` 转义纪律：注入块中文必须转成 `\uXXXX`
- **对策**：**门禁 needle 若落在注入块内，必须写转义形态**，否则永远假 FAIL（已踩 1 次）

### 坑 3：门禁之间自相矛盾
- 例：一条要求「保留 `F0(`」、另一条要求「`F0(` = 0」（已踩 1 次）
- **对策**：写门禁后**通读一遍**找矛盾；「存量守恒」用 `>= N`，「必须消失」用 `== 0`，**不写 `== N`**

### 坑 4：静态检查抓不到的错（**第五例最凶**）
- 已踩 5 例：`md:w-1/3` 死类 / K5 锚点尾段 / `YLXW_COMP.X` 自挂载 / 注入块作用域 depth=3 /
  **`db.run(...).catch()` 顶层 TypeError**
- **对策**：`node --check` 只验语法 ⇒ 必须补**启动冒烟**（`node <产物>` 起一次看能否 listen）

### 坑 5：回调式 sqlite3 没有 Promise
- `db.run()` / `db.get()` 返回 `Database` 对象，**`.catch` 是 `undefined`**
- 本仓驱动 `:86` `new sqlite3.Database` ⇒ 回调式
- **对策**：建表统一用**裸 `db.run(...)`**；门禁 `db.run(.*).catch(` == 0

### 坑 6：服务端是 ESM
- 头部 11 处 `import` + `fileURLToPath(import.meta.url)`
- **`require` 未定义** ⇒ 用了就抛（`loadGameDicts()` 踩过，`/api/gm/dicts` 返回 `{}`）
- **对策**：用 `import`；门禁 `require(` == 0

### 坑 7：基座指纹是全链信任根
- `BASE_FP` 一改 ⇒ 前面所有环的验证基准全废
- **对策**：一切新增改动走**新增末环**，永不改基座（除非整批重做）

### 坑 8：链装配「能装出来」≠「能跑起来」
- 16 环全绿 + `node --check` rc=0，产物却会在启动时炸（坑 4 第五例）
- **对策**：产物落盘后**必须启动冒烟**

### 坑 9：「数据在」≠「通道在」
- 例：`save_snapshots` 表有 90 行真实数据，却**零个读取端点** ⇒ 不是"前端白捡"
- **对策**：声称某功能"白捡"前，先 grep 端点是否存在

### 坑 10：路径泄漏 ≠ 凭据泄漏
- 例：634 处「Oracle 私钥*路径*」命中被当高危；实测 **PEM 私钥本体零命中**
- **对策**：区分「引用了凭据路径」与「凭据本体落盘」

### 坑 11：★★★「删库重测」必须先证明「库真的没了」
- 例：i2-srv-2 反复"删库重测不复现"，实为**删错路径** ⇒ 一直在测**存量库**
  ⇒ 把 **100% 必崩**误判为"不复现"，连续翻车两次
- 本仓 DB 路径有**三分支**：`defaultDbDir = basename(__dirname)==='server' ? __dirname : resolve(cwd,'server')`，
  另有 `DATABASE_PATH` 覆盖
- **对策**：删库后**必须 `ls -la <具体库文件>` 打印确认"文件不存在"**再启动；
  且优先在**独立全新目录**跑，不复用跑过的 sandbox
- ★ 与「先核对监听 PID 是不是自己起的那个」**同一性质：测量对象必须是确定的那个**

### 坑 12：★ 守卫「读 schema 再决定要不要 DDL」不可靠 —— 迁移 DDL 必须幂等
- 例：`rankings` 空库冷启动必崩。`CREATE TABLE`（:181）与 `PRAGMA table_info`（:380/:388）
  在**不同 serialize 块**、**无完成屏障** ⇒ PRAGMA 读到**空 schema**（实测 `rows=0`）
  ⇒ 守卫误判缺列 ⇒ 对**已含该列的表**重复 `ADD COLUMN` ⇒ `duplicate column name` 崩
- 为什么线上不炸：存量库 schema 已落地，PRAGMA 读得到 ⇒ 守卫正确 ⇒ 不 ALTER
- **对策**：
  - ⛔ 不要用「加 `rows.length > 0`」那种**降低概率**的写法（空集 ≠ 表不存在，也可能是"schema 未落地"）
  - ✅ **让 DDL 幂等**：`db.exec(ddl, e => { if (e && !/duplicate column name/i.test(e.message)) console.error(...) })`
    —— **不依赖读到的 schema 是否可信 ⇒ 唯一根治**
  - 红线：只吞 `duplicate column name` 一种，其余 sqlite 错误必须照报

### 坑 13：复现时序 bug 必须在**真实产物完整上下文**里插桩
- 例：P0② 最小复现脚本写了 **9 个全不崩**，因为真实代码里两条 serialize 块之间夹着几十条建表语句，
  累积队列深度才让 PRAGMA 拿到空快照
- **对策**：不要在最小脚本上"证明不存在"；**在真实产物上插桩打点**（`Date.now()-T0`）看真实次序
- ★ 同理：**"跑不崩"不等于"没有 bug"**，可能只是没触发到那个时序

### 坑 14：契约门禁 4 类自毁写法（本日 T7 §2.8 实际踩全）
1. **与正文自相矛盾**：§6.2 要求「保留 `for(;m>0;)`」，门禁却要求该串 = 0
2. **needle 落在注入块内却写中文**：注入块经 `zh()` 转义 ⇒ 产物里是 `\uXXXX` ⇒ 字面中文恒 0
3. **needle 是另一符号的子串**：裸 `YlxwInhInject` 被 `YlxwInhInjectRate` 污染（实测 4 非 1）
4. **needle 未做切片限域**：`F0(` 全文 expect=0，但低境界分支**必须**用它（2 处合法）
- **对策**：写完门禁**通读找矛盾**；**真读产物验证每个 needle 计数**，不凭记忆写；
  「存量守恒」用 `>= N`，「必须消失」用 `== 0`；跨分支的断言必须**切片限域**

### 坑 15：★ `replace(old,new)` 式注入会**静默吃掉锚点函数定义**
- 例：T2 第 19 环新块未把锚点原文带一遍 ⇒ `clampPetDetail` 函数定义被整段替换掉
  ⇒ `/api/pet/adopt` 500 `clampPetDetail is not defined`（**静态读码与 `node --check` 都抓不到**）
- **对策**：新增块必须写成 `NEW_BLOCK = ANCHOR + NEW_BODY`（锚点原文逐字保留在首部）；
  补 **`_assert_anchor_kept()` 自毁防线**：`assert old in new`，不满足直接中止补丁
- ★ 与坑 4「静态检查抓不到的错」同族，第 7 例

### 坑 16：★ 结算/扣费顺序 —— **必须先结算、后扣费**，否则有资损窗口
- 例：融合 UPDATE 引用了未声明的 `sub_consumed` 列 ⇒ `no such column` 抛错 500
  **且余额已扣 10000 灵石、未退回** ⇒ 玩家资损
- **对策**：**先做会抛错的结算（UPDATE + 列声明校验），确认成功后再扣费**；
  扣费失败才走补偿回滚。**永远不要让「先扣钱」出现在「可能失败的操作」之前**
- 加门禁：断言「结算 UPDATE 先于 `updatePlayerSave`」+「块内引用的列都已声明」

### 坑 17：★ 编排者禁止「派门禁的同时让别人改末环」—— 那是射击移动靶
- 例：lead 同时派「最终门禁」与「第 19 环实现」⇒ 门禁测的是中间态，结果当场过期
- **对策**：**末环链是唯一串行资源**。改末环期间**不得**派任何依赖末环的门禁/验证；
  顺序必须是「实现 → 声明定稿（报准确 md5）→ 冻结 → 门禁」
- ★ 同理：成员报「完成」后**可能仍在迭代**（本次连写 4 次）⇒ 判定定稿要看
  **产物 mtime 是否停止增长**，不是看它说了什么

### 坑 18：★ 版本号与 CHANGELOG 是**发布完整性**的一部分，最易漏
- 例：0.8.9 批次全部代码落盘，但 `YLVERSION_FALLBACK` 仍是 `0.8.8`、CHANGELOG 无 0.8.9 条目
  ⇒ 玩家看到**错误版本号** + 一大批改动**在更新日志里不存在**
- **对策**：上线前检查清单**必须含**「版本号三处同步（`yl_version_ext.py` 常量 + 其门禁 + `dryrun_087.py`）
  + CHANGELOG 新条目」。注意这三处**互相断言**，改一处必改其余两处否则门禁 FAIL

### 坑 19：★ 加参数/加字段必须**全仓搜消费点**，漏一处就炸
- 例：给门禁 5 元组加可选第 6 元（`within` 限域）时，只改了 `build_v26n` / `dryrun_087` 两处，
  **漏了 `yl_patch.run()`**（`yl_patch.py:200`）⇒ 跑 `chain_build.py --client` 时
  `ValueError: too many values to unpack (expected 5)` 才暴露。实际漏 3 处
  （`yl_patch.py:200` + `dryrun_modules.py:103` + `_lead_flow_check.py:102`）
- **对策**：改共享数据结构的**元数/字段**前，先 `grep` 出**所有解包点**再动手；改完跑**官方入口**
  （`chain_build.py`）验证，而不是只跑自己那条路径

### 坑 20：★★ CHANGELOG 是「对玩家的承诺」—— **必须按代码实测写，不能按策划案写**
- 例：0.8.9 CHANGELOG 写「灵宠现在**真正参与战斗并提供加成**」，但实测：
  `YlxwPetBonusTotal` 的**唯一消费点是 `YlxwPetStatRow`（角色面板显示行）**，
  全仓无战斗/伤害侧引用 ⇒ **加成只是「面板上显示数字」，没接进战斗结算** ⇒ 过度承诺
- **判据（可复用）**：想声称「某加成生效于战斗」，必须找到**战斗层消费点**。
  对照正确范例 `yl_bond_ext.py`：羁绊补了**两个**消费点 —— 属性层 `YlxwStatExtras` **+** 战斗层 `YlxwBattleBonus`
- **对策**：写 CHANGELOG 前对每条功能 `grep` 出**消费点**（不是定义点）；
  只写「玩家能真正体验到」的程度。定义存在 ≠ 生效
- ★ 同族：坑 9「数据在 ≠ 通道在」。这里是「**函数在 ≠ 生效**」

### 坑 21：★ 停沙盒服务**别用 `pkill -f <路径>`** —— 会匹配到执行它的 shell 自身
- 例：`pkill -f "yl_mail_sandbox/index.ts"` 的**模式串出现在执行命令的命令行里** ⇒ 匹配到自己 ⇒
  ssh 会话被杀（exit 255）。本次未造成损害，但属真实自伤
- **对策**：停沙盒一律**用端口反查 PID**：`ss -ltnp | grep ':<port>'` 拿 pid 再 `kill <pid>`；
  或用 `kill $(lsof -ti:<port>)`。**永远不要用 `pkill -f` 匹配自己刚敲过的路径串**
- ★ 同族：坑 11「测量对象必须是确定的那个」——`pkill -f` 打的是"匹配到的全部"，不是"我以为的那一个"

### 坑 22：★★★「修掉 A 才暴露 B」—— 两个 bug 会**叠着**，必须重验整区
- 实例（T9 环，2026-09-29）：同一处 `collectDailyActivity` 里**叠了两颗雷**
  1. `quests: questList` 引用了已出作用域的变量 ⇒ `ReferenceError` ⇒ **崩进程**（全服宕机）
  2. `grottoN` 被引用却**从未声明** ⇒ 同一函数恒 reject ⇒ `/quest/summary` 恒 500、`/quest/chest` 恒 500
  ⇒ **第 1 个把第 2 个完全遮住了**：进程直接死，根本轮不到 500。
  实测：修掉第 1 个后，`/quest/summary` 由「进程 exit」**变成**「500」——第 2 个才现形
- **对策**：
  - **修完一个 bug，必须重验整个区域**，不能只验那一个点（"修好了"≠"这区好了"）
  - 一个函数/路由内**同时**存在「崩进程级」与「500 级」缺陷时，**从重到轻逐个修、每修一个重验一次**
  - 扫查同类 bug 时，**同一区域要反复扫到干净**（第一个雷会掩盖后面的）

### 坑 23：★ 节流/限频逻辑被复用到「高危不可逆操作」上 ⇒ 丢失退路
- 实例：`snapshotOldSave()`（`:2149`）对写档快照有 **10min 节流**（`:2155`）
  ⇒ 回档端点（`:2541`）调它做「回档前自动存档」时**也走节流**
  ⇒ **10 分钟内连续回档两次，第二次没有退路快照 ⇒ 第二次回档不可逆**（事故）
- 作者注释自己写着「回档前把当前档再存一条（**否则回档不可逆**；`snapshotOldSave` 自带 <10min 节流）」
  —— **知道会走节流，但没处理"节流命中就失去退路"这个后果**
- **对策**：把「写档快照」的节流**直接复用到回档路径**是语义错误 ——
  **写档丢一次快照无所谓；回档丢退路是事故**。高危不可逆操作应**绕过节流**或强制落一条

### 坑 24：★ 敏感串扫描的「自指漏检」—— 报告在解释排除时**把敏感串抄进了自己**
- 实例：`docs/PUBLISH-MANIFEST.md:121` 写「⚠️ 含真实凭据（…真实服务器 IP `47.243.x.x` /
  `161.33.169.210` / `47.109.0.242`），**绝对排除**」—— 这一行**把三个真实 IP 原样写进了将要公开的清单**
- 而扫描把它判为「无害（报告自述文字）」⇒ **漏检**
- **对策（判据修正）**：
  - **「扫描报告里的自述文字」不是豁免理由**。只要**最终会公开的文件**里出现
    **完整 IP / 完整凭据**，就是泄露 —— 不管它是代码、注释、还是"解释为什么排除"的说明
  - 报告里引用敏感串时，**必须打码到网段级/前缀级**（`47.243.x.x`、`csk-****`）
  - **豁免边界**：网段级打码（`161.33.*`）**可接受**；完整串**不可接受**
- ★ 同族：坑 10「路径泄漏 ≠ 凭据泄漏」的**反向**——这里是「自以为无害的自述，其实是泄漏」

### 坑 25：★ 用户名 / 本机路径也是隐私，会随公开仓库一起走
- 实例：脱敏时只想着 IP 与凭据，漏了 `C:/Users/<USER>`（`<USER>` = 本机用户名），
  它出现在扫描命令字面量与文档示例里
- **对策**：公开发布前，脱敏清单**必须包含**：真实 IP、凭据本体、**本机用户名 / 绝对路径**、
  内网主机名、邮箱。统一换成 `<USER>` / `<WORKDIR>` / `<PROD_IP>`

### 坑 26：★★★ 改一行前先全仓 grep —— **别人可能把你要改的行当「基线未动」needle**
- 实例（0.8.10 P2 环，全链首跑 **5 条门禁 FAIL**）：
  - `build_v26n.py:896` 的 `YLXW_COMP 原 23 项仍在` 与 `yl_t8mentor_ext.py:382` 的 `T8·注册锚保留`
    都把 `stats: YlxwTStats };` 当基线 needle ⇒ 我改成 `stats: YlxwTStats, snapshot: … };` ⇒ 两条 FAIL
  - `yl_arb_ext.py:596/599` 把 `var ylArbD=YLArbDecide(Number(...));` 与
    `try{const c=ho(a.player);var ylArbD=YLArbDecide(` 当基线 needle ⇒ 我把整段包进三元 ⇒ 两条 FAIL
- **对策**：
  1. 改任何一行前，**全仓 grep 该行字面量**，确认没有别的模块/门禁把它当 needle；
  2. 新增逻辑优先用 `insert_after` / `insert_before` **追加独立语句**，不改基线行
     （基座既有写法可抄：`YLXW_COMP.mentor=…` / `YLXW_COMP.farm=…`）；
  3. 若必须改「守卫条件」，**只改条件本身**，被当作 needle 的调用行一字不动。
- ★ 同族：坑 1「needle 是另一个符号的子串」的**跨模块版本** —— 坑 1 讲同一门禁内，这里讲**跨文件互相钉死**。

### 坑 27：★ `deploy_*.sh --dry-run` 会把 DEPLOY_LOG 模板**真的落盘**
- 实例：`step 6` 的 `if [ ! -f "$LOG" ]` 不在 `run()` 里 ⇒ dry-run 也执行 ⇒ 先落一份带占位值的
  `DEPLOY_LOG_0.8.x.md` ⇒ 真实部署时走 else 分支 ⇒ **采集到的实测 md5 永远不会写进日志**。
- **对策**：模板生成加 `if [ "$DRY" = 1 ]; then echo "[dry-run] 跳过"; elif [ ! -f "$LOG" ]; then …`
- ⚠️ **0.8.9 及更早的 deploy 脚本仍有此坑**（历史脚本未回改）；0.8.10 起已修。

### 坑 28：★★ remote_check 的**预期计数必须本地预演**，不能靠推断
- 实例：我凭「0.8.9 的 farm089 覆盖了 `YLXW_COMP.farm`」推断 `YLXW_COMP.farm=YlxwTFarmT10` 应为 `eq 0`，
  实际产物里该行**仍在**（count=1，只是运行时被后面的 T5 赋值覆盖）。
  若不预演，要等到**部署之后**跑 remote_check 才发现 FAIL —— 那时线上已切包，回滚成本高。
- **对策**：`python localtest/sim_remote_check.py`（0.8.10 新增）
  —— 解析 remote_check 的 `chk` 行，在**本地交付产物**上按同一语义（`grep -o -F | wc -l` ≡ `str.count`）
  跑一遍，**部署前必跑**。本批结果：179 OK / 9 SKIP（远端专有）/ 0 FAIL。

### 坑 29：★★★ 给**已有组件**加 Hook，不能用 `insert_before` 往组件前面插
- 实例（0.8.11 秘境弹窗次数条）：`cM` 组件所在语句的起点**不是** `cM=` 本身 ——
  它的前文是 `},oM=Rt.memo(lM),cM=({isOpen:t,…})=>{…}`，即 `cM` 与 `oM` 在**同一条语句**里
  （逗号表达式链）。`insert_before(A4, code)` 把 code 插在 `,cM=` 之前 = **仍在这条语句内**，
  于是 `O.useEffect(…)` 会在**模块加载时无条件执行一次**，而且拿不到组件实参（`t` / `isOpen`）。
- **对策**：改用 `replace` **原地扩写组件函数体头部**（把 `cM=(…)=>{const[c,d]=O.useState(0),`
  整段作为锚点，替换成 `…useState(0),[新增 state]=…,`）。
- **判据**：插 Hook 前先看锚点前面最近的 `;` 或语句起点 —— 若锚点与目标组件在**同一语句**内，
  `insert_before` 一定错。

### 坑 30：★★★ Hook 必须写在 `const` 声明**闭合之后**，不能塞进声明列表中间
- 实例（同上）：`cM` 形参体是 `{const[c,d]=O.useState(0),u=O.useMemo(…),f=…,v=…;return e.jsx(ct,{…})}`
  —— 只有 `v=…` 之后那**一个分号**是语句边界。
  若写成 `…useCallback(…);O.useEffect(…),u=O.useMemo(…)`：
  ① `;` 提前闭合了 const 语句；② `O.useEffect(…) , u=O.useMemo(…)` 变成**逗号表达式**，
  其中 `u=…` 是**裸赋值**（`u` 未声明）⇒ 严格模式 / ESM 直接 `ReferenceError`，
  整个 bundle 起不来。
- **对策**：新增 Hook 一律挂在**语句边界之后**（本例：`v=()=>{…};` 之后、`return` 之前）。
  `const` 声明列表里只放 `useState` / `useCallback` / `useMemo` 这类**有返回值**的 Hook
  （它们可以当声明符的值）；`useEffect`（返回 undefined）走独立语句。
- ★ 同族：坑 4「注入点落在表达式中间」的**Hook 版本**。

### 坑 31：★ 门禁 needle 太短会被**别的模块的文案**撞车
- 实例：我给 0.8.11 次数条写的门禁 `'\u4eca\u65e5\u79d8\u5883\u6b21\u6570'`（「今日秘境次数」）
  期望 1，实测 2 —— 因为 0.8.5 的 dg085 在 403 分支里有一句
  `"今日秘境次数已用完，明日再来。"`，**这 6 个字是它的子串**。
- **对策**：门禁 needle 带上**足够的上下文**（本例改为
  `className:"text-purple-300 font-bold",children:"…"}`）；改完立刻单模块预演
  （把模块单独打到当前定版 bundle 上跑门禁，**比全链快 20 倍**）。
- ★ 同族：坑 1「needle 是另一个符号的子串」的**跨模块文案版**。
