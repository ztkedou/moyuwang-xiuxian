# 0.9.17 设计输入 · 物品与装备引擎全景（侦察报告）

> 生成：2026-10-03 ｜ 基线：**0.9.16 线上版**（`build/assets/index-v2916-20261003.js`，md5 `a59ac4496ab0e8ab81fdb147b45488ec`）
> 对应需求：**R-140**（可使用物品数值重构）／**R-141**（高品质装备稀有属性）
> 本文只做「事实 + 插入点」记录，不含最终数值方案。

## 0. 一句话结论

**两条线都远比预期好做。** 引擎里**早就存在**一整套「稀有属性（暴击率/暴击伤害/闪避/吸血/减伤）」的生成 + 聚合 + 封顶 + 战斗消费链路（R-018b 洗炼 / 羁绊 / 灵纹），
**只是掉落/奖励产出的装备从不带这些词条**，必须玩家自己花「太虚洗炼石」去洗。R-141 的本质 = **让高品质掉落装备天生带词条**，而不是从零新建机制。
R-140 同理：**R-135（已在 0.9.16 上线）就是这条线的第一遍**，R-140 是把它做彻底。

### 3.1 装备属性生成器 `iy` @316759

  S = mg[rarity];  x = (S.min + S.max)/2

  for key in [attack, defense, hp, spirit, physique, speed]:
    if key is spirit|speed:                   // ★★ 独立硬编码分支（用户要求「不动」的部分）

### 3.8 ★★ 物品入包的**唯一漏斗** `vs()` @632245（两条线都必经此处）

```js

```

**三条必须记住的推论**：
1. **`vs()` 逐字段白名单重建对象** ⇒ 在 `cy()` / `_y()` 上挂的自定义字段（如词条）**会被静默丢弃**。R-141 的注入点只能是 `vs()` 内部。
2. **消耗品按 `name` 合并堆，且整堆 `effect`/`permanentEffect` 被新值覆写** ⇒ 老玩家手里的存量物品**会在再次获得同名物品时自动刷新为新数值**（R-140 的存量兼容性比原先判断的乐观）。
3. **`ry` 的 `noScale` 只对装备短路**，消耗品永远吃 `ny`/`fg` ⇒ 「`ny` 不动」是安全的。

## 4. 已定版约束（不可违反）

1. **神识 / 身法（spirit/speed）不改** —— 它们走 `iy` 里的独立硬编码分支，动它必崩断言面（R-107 ÷10 等）
2. **奇物类（升段一次性）不改** —— 候选 = `breakthrough` 7 条
3. 封顶不得突破 `YlxwBattleCapCfg`（暴击35% / 暴伤100% / 闪避35% / 吸血25% / 减伤50%）
4. 任何改动必须走「**standalone 契约**」（`--src` / 原子写回 / `.bak` / 幂等 rc=3 / `gates()` / `_precheck()` + 往返自证），**不进 `V28_MODULES`**
5. 上线时 **升版 7 处**（含 `deploy_v2811.sh` + `remote_check_v2811.sh` 的 `BUNDLE_DATE`）
6. ⚠ **热修 index.html 必须用 `deploy_v28/live_bump_bundle.js` 原地 patch**，禁止直传 `build/index.html`（0.9.15 的回归根因）
