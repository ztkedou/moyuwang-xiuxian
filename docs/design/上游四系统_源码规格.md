**三条最重要的发现（移植决策关键）：**

1. **洗炼的暴击/暴伤/闪避/吸血词条上游从未生效。** `utils/statUtils.ts:372` 定义了 `getEquippedReforgeSpecialStats()`，但**全仓库无任何调用点**（已 grep 确认）。真正进战斗的只有 `attackPercent / defensePercent / hpPercent` 三条，通过 `getPlayerTotalStats()` 生效。→ 移植时若想 4 条特殊词条真生效，需要我方**自己补**消费逻辑（上游是半成品）。
2. **通天塔完全独立于 `battleService`。** `towerService.challengeTowerFloor` 内部自己写了一套回合制数值博弈（25 回合上限、速度决定先后手、`Math.random()*0.2` 浮动），只调用 `getPlayerTotalStats(player)` 取玩家面板。→ **移植通天塔零战斗耦合**。
3. **SectModal / DungeonModal 的改动不属于四系统。** `SectModal.tsx`(+141/−17) 实际是"宗门修炼室 / 宗主俸禄 / 宗门职位属性加成 / 任务刷新消耗"；`DungeonModal.tsx`(+62/−33) 只是 **emoji→lucide 图标重构 + effect 级联重渲染修复**。两者与四系统无关，移植时可忽略。

/** 每日扫荡基准收益 */
export function calculateTowerDailySweep(highestFloor: number): {
  exp: number;
  spiritStones: number;
  reforgeStones: number;
  items: Item[];
} {
  if (highestFloor <= 0) {
    return { exp: 0, spiritStones: 0, reforgeStones: 0, items: [] };
  }

  // 扫荡收益为所通关层数累计价值的约 35%
  let totalExp = 0;
  let totalStones = 0;
  for (let f = 1; f <= highestFloor; f++) {
    totalExp += Math.floor(150 * Math.pow(1.045, f) + f * 50);
    totalStones += Math.floor(100 * Math.pow(1.04, f) + f * 35);
  }

  const reforgeStones = Math.max(1, Math.floor(highestFloor / 8));
  const items: Item[] = [createReforgeStoneItem(reforgeStones)];

  if (highestFloor >= 50 && Math.random() < 0.6) {
    items.push(createComprehensionScrollItem(1));
  }

  return {
    exp: totalExp,
    spiritStones: totalStones,
    reforgeStones,
    items,
  };
}

### B. 函数规格 —— `services/towerService.ts`（288 行）

依赖：`../types`(PlayerStats, Item)、`../constants/tower`、`../utils/statUtils`(getPlayerTotalStats)、`../utils/inventoryUtils`(addItemToInventory)、`dayjs`。

#### B1. `challengeTowerFloor(player, floorToChallenge)`
- 签名：`(player: PlayerStats, floorToChallenge: number) => { result: TowerChallengeResult; updatedPlayer: PlayerStats }`
- 逻辑：
  1. 读 `player.tower?.highestFloor || 0`；跨层校验 `targetFloor > currentHighest + 1` 直接拒绝；`>100` 拒绝。
  2. `getTowerFloorConfig(targetFloor)` 取守关者；`getPlayerTotalStats(player)` 取玩家面板。
  3. **自带回合制模拟**：`maxRounds=25`；`playerFirst = pSpeed >= gSpeed`；伤害公式
     - 玩家打守关：`Math.max(1, floor(pAttack*(1+random*0.2) - gDefense*0.4))`
     - 守关打玩家：`Math.max(1, floor(gAttack*(1+random*0.2) - pDefense*0.45))`
     - 25 回合未分胜负 → 按剩余血量百分比 `pHp/playerStats.maxHp >= gHp/baseHp` 裁决。
  4. 胜利：仅当 `targetFloor > currentHighest` 视为首通，发首通奖励（exp/灵石/洗炼石/悟道卷/特殊物品）；非首通不发奖。
  5. 失败：`hp = max(1, floor(maxHp*0.15))`。
- **读写存档字段**：
  - 读：`player.tower.highestFloor`、`player.hp`、`player.maxHp`、`player.exp`、`player.spiritStones`、`player.inventory`、`player.realm`、`player.realmLevel`、以及 `getPlayerTotalStats` 依赖的全部面板/装备字段。
  - 写：`player.hp`、`player.exp`、`player.spiritStones`、`player.inventory`、`player.tower.{highestFloor, dailySwept, lastSweepDate}`。
- 依赖：`getPlayerTotalStats`、`addItemToInventory`、`getTowerFloorConfig`、`createReforgeStoneItem`、`createComprehensionScrollItem`。
- **含随机数**：是，`Math.random()`（伤害浮动）。**服务端不可复现**（如需防作弊需改造）。

#### B2. `sweepTower(player)`
- 签名：`(player: PlayerStats) => { success: boolean; message: string; updatedPlayer: PlayerStats; rewards?: {exp; spiritStones; items} }`
- 逻辑：读 `player.tower`；`highestFloor<=0` 拒绝；`lastSweepDate===today && dailySwept` 拒绝（每日一次）；调用 `calculateTowerDailySweep(highestFloor)`；物品入库；写 `dailySwept=true, lastSweepDate=today`。
- **读写存档字段**：读 `player.tower.*`、`player.inventory`、`player.realm/realmLevel`；写 `player.exp`、`player.spiritStones`、`player.inventory`、`player.tower.dailySwept/lastSweepDate`。
- 依赖：`dayjs`、`calculateTowerDailySweep`、`addItemToInventory`。
- **含随机数**：间接（`calculateTowerDailySweep` 内 `Math.random()<0.6` 决定悟道卷）。用 `dayjs().format('YYYY-MM-DD')` 做每日判定的**本地时间**。

#### 无导出常量以外的东西；`TowerChallengeResult` 为导出接口。

### B. 函数规格 —— `services/petExpeditionService.ts`（270 行）

依赖：`../types`(PlayerStats, PetExpedition)、`../constants/petExpedition`、`../utils/gameUtils`(uid)、`../utils/inventoryUtils`(addItemToInventory)。

#### B1. `startPetExpedition(player, petId, locationId)` （导出）
- 签名：`(player, petId: string, locationId: string) => { success; message; updatedPlayer }`
- 逻辑：校验 `player.grotto && grotto.level>=1`；`player.pets?.find(id)`；`EXPEDITION_LOCATIONS.find(id)`；`pet.level >= location.minPetLevel`；`getUnlockedExpeditionSlots(grotto.level)` 槽位（`status!=='claimed'` 计为占用）；同一灵兽不能重复派遣。
- 构造 `PetExpedition`：`id=uid()`、`startTime=Date.now()`、`duration=location.durationMs`、`endTime=now+duration`、`status='exploring'`。
- **读写存档字段**：
  - 读：`player.grotto.level`、`player.grotto.petExpeditions`、`player.pets[].{id,name,level}`。
  - 写：`player.grotto.petExpeditions`（追加一条）。
- **含随机数**：仅 `uid()`（非玩法随机）。

#### B2. `checkAndUpdateExpeditions(player)` （导出）
- 签名：`(player: PlayerStats) => PlayerStats`
- 逻辑：无 grotto / 无远征直接返回原对象（**引用相等**，供 UI 判断是否变更）；遍历，把 `status==='exploring' && now>=endTime` 的标记为 `'completed'` 并**即时生成 rewards**（`loc.generateRewards(petLevel)`，`petLevel = pet?.level||1`；找不到地点给 `{spiritStones:500, exp:800, items:[]}`）。
- **读写存档字段**：读 `player.grotto.petExpeditions`、`player.pets[].level`；写 `player.grotto.petExpeditions[].{status, rewards}`。
- **含随机数**：是（**奖励在"完成检测"时就掷点**，`Math.random` 大量）。

#### B3. `claimPetExpedition(player, expeditionId)` （导出）
- 签名：`(player, expeditionId: string) => { success; message; updatedPlayer }`
- 逻辑：找 `status==='completed' && rewards` 的记录；物品入背包；从列表移除该条；发灵石/修为。
- **读写存档字段**：读 `player.grotto.petExpeditions`、`player.inventory`、`player.spiritStones`、`player.exp`；写 `player.spiritStones`、`player.exp`、`player.inventory`、`player.grotto.petExpeditions`（移除）。
- **含随机数**：否。

#### B4. `recallPetExpedition(player, expeditionId)` （导出）
- 签名：同 B3。逻辑：直接从列表移除（**放弃奖励**）。
- 读写：`player.grotto.petExpeditions`。**无随机**。

**最难移植：自创神通。** 难在三点：
1. **战斗耦合最深**——它同时改 `utils/statUtils.ts`（面板）和 `services/battleService.ts` 的两条战斗路径（`resolveBattleEncounter` 自动战斗 + `createBattleUnitFromPlayer` 回合制），且要动暴击上限（0.2→0.35）、暴击倍率（1.5→1.5+bonus）、新增闪避/减伤/吸血结算分支。我方 bundle 是**压缩产物 + 锚点补丁**，改战斗结算分支的锚点定位与注入风险最高。
2. **依赖上游功法表**——`CULTIVATION_ARTS` 的 `grade`/`effects.attack/defense/speed/hp/physique` 字段语义必须与我方一致，否则 `calculateFusedSpellEffects` 生成的数值会跑偏。
3. **UI 嵌在既有 `CultivationModal` 内**，且要新增 `applyCustomSpellOp` 写回逻辑，锚点比独立新文件难找。

**最容易移植：九天通天塔。** 它是**独立新文件 + 自带战斗模拟**，只需在 `uiStore` 加一个 `isTowerOpen`、在 `AppContent` 挂载、在 `SecretRealmModal` 加入口即可。唯一注意点是它自带 `Math.random` 战斗，服务端不可复现（若我方有防作弊需求需另行处理）。

**次易：灵兽远征**，纯计时 + 掉落，但**必须确认我方物品表含那 10 个中文物品名**，否则掉落静默丢失。

**洗炼的隐藏坑**：4 条特殊词条（暴击/暴伤/闪避/吸血）**上游是死代码**——`getEquippedReforgeSpecialStats()` 定义了却无人调用。若只照搬上游，玩家能洗出这 4 条却毫无效果，属于**"看起来能用、实际没效果"的假功能**，需我方自行补齐消费逻辑。
