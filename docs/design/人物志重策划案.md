## 1. 现状诊断（为什么必须重做）

### 1.1 事实核查（源码 + 线上截图）

`人物志` 在基线 bundle 里共出现 **5 次**，全部指向同一套东西：

| # | 偏移 | 位置 | 作用 |
|---|---|---|---|
| 0 | 711417 | 角色面板「人际关系」卡片 | `title:"查看人物志"` |
| 1 | 712258 | 同上（未结识分支） | 卡片标题 `人物志` |
| 2 | 712346 | 同上 | `title:"查看人物志"` |
| 3 | 740457 | 顶部工具栏「人物」按钮 | `title:"人物志"`，角标 = `socialRelations.length` |
| 4 | 1331247 | **模态框本体**（组件 `Nk`） | `title:"人物志", size:"lg", height:"lg"` |

数据源：`player.socialRelations[] = {id, name, favorability(-100..100), description, lastEncounterRealm}`。
**纯客户端字段**（服务端 `index_v27b.ts` 全文 grep `socialRelations` → 0 命中），随 `/api/save` 整包落库。

写入路径只有一条：历练/抉择事件里 **10% 随机**命中
（`!u.npcRelationChange&&Math.random()<.1&&(u.npcRelationChange={npcId:"npc-random-"+(1+Math.floor(Math.random()*8)), npcName:[8个名字][Math.floor(Math.random()*8)], favorabilityChange:3+Math.floor(Math.random()*8), description:"在一次历练中偶然结识的道友"})`）。

> 注意上游同款 bug：**`npcId` 与 `npcName` 是两次独立随机**，所以 `npc-random-3` 在一台机器上叫「散修剑客」、在另一台上可能叫「摆摊老者」。我方原样移植了。

面板内容（`Nk`）：
- 顶部「人际关系加成」汇总（`expBonus` / `stoneBonus` / `daoCompanion` / `huntChance`）
- 左侧关系列表（按好感度排序）＋ 右侧详情（好感度条、描述、结识境界、效果）
- 两个动作：赠送物品（按装备属性折算好感）、赠灵石 100 → +5 好感
- 空态：`尚未结识任何道友，多在历练中闯荡吧。`

**线上实测截图**：`recon_char_panel.png`（账号 `ylui0927a`，`socialRelations` 为空）
→ 一个 `size:"lg" height:"lg"` 的大模态框，**里面只有一行灰字**。这就是用户说的「需要重新策划」。

### 1.2 上游参考结论

上游 `JeasonLoop/react-xiuxian-game @1ec1b63`：
- `components/NPCRelationsModal.tsx`（254 行）= 我方 `Nk` 的 1:1 移植（`getFavorLevel` / `getFavorBuff` / 赠送 完全同构）
- 触发点：`views/adventure/executeAdventureCore.ts:271`、`hooks/useBattleResultHandler.ts:176`、`hooks/useReputationEventHandler.ts:105`
- 模板侧还有若干命名 NPC：`灵泉守护者 / 采药修士 / 同修道人 / 散修旅人`（`adventureTemplateService.ts:535`）、`隐世前辈 / 古修残魂 / 道韵化身 / 灵识投影`（:427）

→ **上游同样没有收集、没有图鉴、没有传记、没有进度、没有奖励。** 所以这次是**纯新增设计**，不是「把上游没搬完的搬完」。

### 1.3 五条致命问题（按严重度）

1. **没有目标**：8 个随机 NPC 纯靠 10% 概率撞，玩家无法主动追求任何一位。
2. **没有收集动机**：面板不显示「共有几位 / 我还差几位」，玩家连「收集」这件事都不知道存在。
3. **投入产出倒挂**：100 灵石 = +5 好感，涨满 100 要 ~2000 灵石，只换 **+10% 修炼速度**；而 20 位道友都刷满也就那样，中间没有任何里程碑兑现点。
4. **没有「志」**：名字随机、无背景、无传记。叫「人物志」却没有任何「人物」。
5. **空态即死局**：新号打开是一行灰字，无引导、无出口。

## 2. 新设计总纲

> **一句话**：把「随机遇到的 NPC 名单」升级为 **可主动追求、有收集进度、有里程碑兑现、有传记文本、有永久收益的《道友图鉴·缘契》**。

### 2.1 核心循环

```
【寻访】花灵石 / 每日免费一次，定向结识新道友
      ↓  （结识 → 图鉴点亮，永久 +修炼速度）
【送礼 / 赠灵石】提升该道友的「缘契值」(0~100)
      ↓
【缘契里程碑】25 相知 / 50 知己 / 75 莫逆 / 100 道侣 → 一次性领奖
      ↓
【传记】缘契 50 解锁【小传】，100 解锁【秘辛】（世界观文本 + 大奖）
      ↓
【图鉴收集】已识 3/6/9/12/16/20/24 位 → 阶段性收集大奖（含仙品信物）
      ↓
   修炼速度永久提升 → 更快变强 → 更想集齐
```

**为什么继续做**：每点亮一位道友 = 永久 `+0.3%~1.2%` 修炼速度（集齐额外 +2%），并且立刻兑现灵石/修为；`缘契 100` 的【秘辛】是「人物志」里最有价值的信息与最大一笔奖励。

### 2.2 与既有系统的边界（防重复）

| 系统 | 归属 | 与人物志的边界 |
|---|---|---|
| 成就（`/api/achievements`） | 服务端，全局里程碑 | 人物志**不新增成就**，只做 NPC 收集；两者文案不复用 |
| 称号（`player_titles`） | 服务端 | 人物志**不发称号**（`【xx】` 只在日志/面板内显示，不入 `unlockedTitles`） |
| 榜单（`/api/leaderboard`） | 服务端 | 不参与 |
| 仙友录 / 师徒 / 结拜 / 道侣（`/api/friends`、`/api/sworn`、`/api/couple`） | **真人玩家**社交 | 人物志是 **NPC**，与真人系统零耦合、零数据共享 |
| 江湖志（`/api/chronicle`） | 服务端纪事 | 人物志**不写江湖志**，避免刷屏 |
| 好感度 buff（`xt` 内 `+10%/+5%`） | 既有 | **原样保留**，我只在同一个 `S` 变量上**追加**图鉴收集项 |

## 3. 系统设计

### 3.1 图鉴（24 位道友）

- **凡缘 12 位 / 仙缘 8 位 / 天缘 4 位**，共 24。
- 前 8 位**沿用既有 `npc-random-1..8` 的 id 与既有 8 个名字** → 老玩家已有的关系**自动点亮**，零迁移成本。
- 后 16 位为新增（id `npc-dex-9..24`），取自上游模板里出现过的命名 NPC + 补足。
- 每格：未结识显示 `？？` + 剪影态；结识后显示名字 + 稀有度配色；点击看详情。
- 详情含：稀有度 / 道号 / 结识描述 / 缘契进度 / 小传 / 秘辛。
- **兼容任意 id**：adventure 模板可能产生 `npc-adventure-xxx-3` 这类动态 id。这类「无名道友」**不进图鉴计数**，但**照样享有缘契里程碑奖励**（见 3.3），面板不报错、不丢失。

### 3.2 寻访（主动结识路径）

| 方式 | 消耗 | 结果 |
|---|---|---|
| 每日免费寻访 | 0（每日 1 次，`charDex.freeDate` 记录日期） | 从未结识池按稀有度权重抽 1 位 → 新结识（缘契 +15~25） |
| 灵石寻访 | `200 × YLRF(player)` | 同上；24 位全部结识后改为「重逢」随机一位 +4~9 缘契 |

权重（未结识池内归一化）：凡缘 60 / 仙缘 30 / 天缘 10。

> 设计意图：给玩家一条**确定性**的追求路径，把「运气」变成「投入」。

### 3.3 缘契值（沿用 `favorability`，不新增字段）

缘契 0~100（负值仍是原有「冷淡/敌视/仇敌」语义，不改）。

| 阶 | 阈值 | 一次性里程碑奖励 |
|---|---|---|
| 结缘 | ≥1 | — |
| 相知 | ≥25 | 灵石 `60 × rf` |
| 知己 | ≥50 | 修为 `120 × rf` |
| 莫逆 | ≥75 | 灵石 `200 × rf` |
| 道侣 | ≥100 | 修为 `400 × rf` ＋ 灵石 `300 × rf` |

`rf = YLRF(player)`（既有境界奖励缩放：炼气 4/3、筑基 3、金丹 5、元婴 7、化神 9、合道 11、长生 13）。

> 里程碑对**所有关系**生效（含无名道友），只有【小传/秘辛】限定图鉴内 24 位。

### 3.4 图鉴收集奖励

| 档 | 条件（已识 N 位） | 奖励 |
|---|---|---|
| 三友 | ≥3 | 灵石 `300 × rf` |
| 六合 | ≥6 | 修为 `500 × rf` |
| 九曜 | ≥9 | 灵石 `800 × rf` |
| 十二楼 | ≥12 | 修为 `1200 × rf` ＋ 同心结 ×1（稀有 Material） |
| 十六尊 | ≥16 | 灵石 `1500 × rf` |
| 二十真 | ≥20 | 修为 `2000 × rf` ＋ 同心结 ×2 |
| 廿四仙 | ≥24 | 灵石 `3000 × rf` ＋ 修为 `3000 × rf` ＋ **道友图谱 ×1（仙品）** |

### 3.5 永久收益（图鉴加成，接进修炼速度）

`YlxwCharDexRate(player) = Σ(已识道友稀有度系数) + (集齐 24 位 ? 2% : 0)`

| 稀有度 | 单位系数 | 满档贡献 |
|---|---|---|
| 凡缘 | +0.3% | 12 × 0.3% = 3.6% |
| 仙缘 | +0.6% | 8 × 0.6% = 4.8% |
| 天缘 | +1.2% | 4 × 1.2% = 4.8% |
| 集齐奖励 | +2.0% | — |
| **合计（满图鉴）** | | **+15.2% 修炼速度（永久）** |

> 接入点：既有 `xt` 内的 `let b=fy(m).expRate||0,S=0;` 之后**追加一行**，不修改任何既有常量、不修改既有 `+10%/+5%` 逻辑。

### 3.6 数值表 · 预期耗时（金丹期 rf=5 为例）

| 目标 | 需要 | 耗时（乐观/一般） |
|---|---|---|
| 第 1 位道友 | 免费寻访 1 次 | 立即 |
| 集齐 12 位（拿同心结） | 免费 1/天 + 灵石寻访 ~12 次 = ~6000 灵石 | 1~3 天 |
| 集齐 24 位 | 免费 24 天 / 灵石寻访 ~24 次 = ~24000 灵石 | 3~10 天 |
| 单人道侣（缘契 100） | 20 次赠灵石 = 2000 灵石 | ~1 天（灵石富余时） |
| 单人全里程碑回报 | 灵石 `560×5=2800` + 修为 `520×5=2600` | **净赚 +800 灵石 + 2600 修为** |
| 全图鉴总回报（金丹） | 收集奖 灵石 28000 + 修为 33500 ＋ 24×(2800/2600) | **远大于投入，且 +15.2% 永久修炼速度** |

> 数值全部为**新增表**（`YLXW_CHAR_BOND_MILE` / `YLXW_CHAR_DEX_MILE` / `YLXW_CHAR_VISIT_COST` / `YLXW_CHAR_RAR[].rate`），未改动任何既有常量。若 T7（全玩法数值重规划）需要调，只改这四张表即可。

## 5. 数据结构（全部落在 `player` 内，随 `/api/save` 落库）

```js
player.charDex = {
  v: 1,
  met:     { "npc-random-1": true, ... },   // 已结识（图鉴点亮，持久）
```

## 6. 验收点（明天用户应看到的 5 件事）

1. **打开人物志（工具栏「人物」或角色面板卡片）**：面板最上方出现「道友图鉴 · 缘契」区块，含 `图鉴收集 0 / 24` 进度条与 `凡缘 0/12 · 仙缘 0/8 · 天缘 0/4`。
2. **点「寻访 · 今日免费」**：日志出现 `【寻访】你结识了【×××】（稀有度），缘契 +××`，图鉴对应格子由 `？？` 变为名字，进度条前进，`修炼速度 +0.3%` 之类数字变大。
3. **点「灵石寻访 N」**：灵石扣除 `N`，再结识一位；同一天再点免费按钮 → 按钮变为禁用「今日已寻访」。
4. **列表里点一位已结识道友 → 右侧详情底部**出现「缘契里程碑」四个 chip；把缘契刷到 25/50/75/100 后 chip 由灰变亮黄，点击领取 → 日志出现 `【人物志】××× 缘契达 50（知己）：修为 +×××`；缘契 ≥50 时【小传】解锁显示文本，≥100 时【秘辛】解锁。
5. **集齐 3 位**：图鉴区「三友」chip 变亮，点击领取 → `【人物志·三友】收集奖励：灵石 +×××`，灵石/修为增加，chip 变绿 ✓。
6. **刷新页面（重新登录）**：以上全部保留（`charDex` 已随存档落库）。

## 7. 为什么服务端零改动

- `socialRelations` 与新增的 `charDex` 都是 `player` 内的普通 JSON 字段；`POST /api/save` 直接 `JSON.stringify(saveData)` 整包落库（`srv/index_v27b.ts:1793`），**无字段白名单**。
- 唯一会动到新增字段的是 `settleSaveEconV2()`（:1612），它只钳制 `spiritStones` / `exp` 的**正增量**上限、以及 `inventory[].quantity` 的 NaN/负值/单组上限；`charDex`、`socialRelations` **完全不受影响**。奖励量级（每档 `300~3000 × rf`）远低于其额度（`E2_LUMP_STONE_ALLOWANCE` + 离线重算兜底）。
- 因此**不新建 `srv_patch_char.py`**，也不动 `srv/index_v27b.ts`。

## 8. 遗留与风险

| 项 | 说明 |
|---|---|
| 客户端权威 | 缘契/图鉴奖励是客户端入账（与本游戏既有存档架构一致），理论上可被改本地存档作弊。**与既有成就/称号同一信任级别**，不新增风险面。 |
| 修炼速度锚点共享 | 图鉴加成接在 `let b=fy(m).expRate||0,S=0;` 之后。若 T7（心法+全玩法数值重规划）重写该函数，需保留这一行（已在报告中标注精确锚点）。 |
| 老存档名字错位 | 上游遗留 `npcId`/`npcName` 双随机导致个别老档 `npc-random-N` 显示名与图鉴名不一致；按 `id`+`name` 双匹配后两格都会点亮，不影响计数与奖励。 |
| 24 位道友文案 | 传记/秘辛为一次性文本，后续若要扩充剧情，只需在 `YLXW_CHAR_DEX` 里改 `bio`/`secret` 字段。 |
| 未做的（有意） | 不加页签、不加抽屉入口、不改工具栏角标（留给 T1 入口可发现性）、不发称号、不写江湖志。 |
