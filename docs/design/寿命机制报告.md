# 摸鱼修仙传 · 寿命机制侦察报告

> 基线：`build/assets/index-v26m-20260927.js`（与线上 v26k 在寿命逻辑上**完全一致**，本轮未改动寿命相关代码）
> 目的：回答「寿命减少的方式」，供决定要不要动它。
> 所有片段均为**逐字取自 bundle**（含偏移），可自行复核。

---

## 0. 一句话结论

寿命有三条扣减通道 + 一条死亡判定：

| # | 通道 | 单次扣减 | 触发频率 |
|---|---|---|---|
| 1 | **历练结算**（主要） | 0.3 ~ 1.5 年 | 每轮历练结算一次 |
| 2 | **离线修炼** | **1 年 / 小时**（上限 24 小时） | 每次离线 |
| 3 | **战斗技（奇物/精华/髓）** | 5 ~ 60 年 / 次 | 手动使用 |
| — | 死亡判定 | `lifespan <= 0` → 寿终正寝 | — |

补充来源（加寿命）：**突破**、延寿类丹药与灵草、部分奇遇的 `lifespanChange`。

## 1. 基础值

```
@247889  lifespan: t.lifespan ?? t.maxLifespan ?? 100
         maxLifespan: t.maxLifespan ?? 100
@496724  新号初始化  lifespan:M, maxLifespan:$   （M/$ 由灵根等推导）
```
- **初始寿命 100 年**，`maxLifespan` 也是 100（寿命有上限，不能超过 `maxLifespan`）。
- 界面警告阈值（@1401905）：
```js
u.lifespan < Math.max(5, (u.maxLifespan || 100) * 0.1)
→ 显示「⚠️ 寿元将尽 (剩余 X 年)」
```
即 **低于 `max(5, 上限×10%)` 就闪红字**。100 年上限时 = 低于 10 年报警。

## 2. 通道 1：历练结算扣寿命（**主通道**）

`@1214992`，位于「应用历练结果」的函数内（同一个函数同时写 `exp / spiritStones / reputation / karma / spiritualRoots`）：

```js
const h = l ? 1 : u==="低" ? .3 : u==="中" ? .6 : u==="高" ? 1 : u==="极度危险" ? 1.5 : .4;
if (S.lifespan = Math.max(0, Math.min(t.maxLifespan,
      (t.lifespan ?? t.maxLifespan) + (r.lifespanChange || 0) - h)), ...
```

| 风险档 | 每轮扣 |
|---|---|
| 低 | 0.3 年 |
| 中 | 0.6 年 |
| 高 | 1.0 年 |
| 极度危险 | 1.5 年 |
| 其它 / 缺省 | 0.4 年 |
| `l` 为真 | 1.0 年 |

要点：
- **它是「每轮历练结算」扣，不是每次奇遇子事件扣** —— 因为 `h` 所在函数一次性写入该轮的全部收益。
- `Math.min(t.maxLifespan, ...)` → **寿命永远不超过 `maxLifespan`**，`lifespanChange` 的加成也会被上限吃掉。
- `Math.max(0, ...)` → 下限钳到 0，不会变负。

> ⚠️ **待实测**：自动历练的结算周期是 3 秒（`setInterval 500ms` + 冷却 3s）。若按「每 3 秒一轮」推算，
> 低危约 **6 年/分钟**、极度危险约 **30 年/分钟**，100 年寿命仅够 3~17 分钟。
> 这个量级与「玩家能正常玩下去」矛盾，所以**实际触发频率需要实测确认**
> （可能只在高风险档或特定事件才结算，也可能自动历练走的是另一条不扣寿命的路径）。
> 这是本报告唯一未闭合的点，需要跑一次 60 秒实测才能定论。

## 3. 通道 2：离线修炼扣寿命

`@538043`（离线结算函数）：

```js
const S = c / (365 * 24) * 365;     // c = Math.min(离线小时, 24)
return { elapsedSeconds:a, elapsedText:d, meditationExp:v, spiritStoneIncome:j,
         grottoHerbs:b, lifespanSpent:S };
```

`@538572`（应用到玩家）：

```js
a.lifespan = Math.max(0, (a.lifespan || 100) - r.lifespanSpent);
```

- 化简后 `S = c`，即 **每离线 1 小时扣 1 年寿命**，最多按 24 小时计（= 最多扣 24 年）。
- 与「离线收益只有 375 灵石/小时」一样，属于象征性惩罚，**不是主要压力**。
- 注意：`Math.max(0, ...)` → 离线也可能把寿命扣到 0 → 直接触发死亡判定。

## 4. 通道 3：战斗技消耗寿命

数据表里 **`cost:{lifespan:N}`**，N ∈ **5 ~ 60**，全部挂在「筑基奇物 / 天地精华 / 天地之髓」类进阶物品的 `battleEffect` 上。例：

```
ft_001 青木灵根  青木回春  消耗10年寿命，恢复30%最大气血
ft_003 玄水精魄  玄水护体  消耗 8年寿命，获得防御力+40%
ft_011 …          九转之力  消耗20年寿命，攻击+50%、防御+30%，持续3回合
ft_040 太极图录  太极平衡  消耗60年寿命，全属性+70%、免疫负面、反弹50%
hee_001 业火红莲 业火焚身  消耗15年寿命，造成攻击力3倍伤害
```

- 是**手动**代价：用寿命换一次爆发。默认带 `cooldown`（2~9 回合），不能无限刷。
- 这是玩家**主动**选择的消耗，不是系统强制扣。

## 5. 死亡判定

`@549838`，一个 `useEffect` 监听 `player.lifespan`：

```js
if (t.lifespan !== void 0 && t.lifespan <= 0) {
  c("⏰ 你的寿命已尽，寿终正寝 还是无缘窥探大道...", "danger");
  const x = [ 4 段随机文案 ];  T = x[Math.floor(Math.random() * x.length)];
  if (d.difficulty === "hard")   // 硬核难度：真死
      l(!0), r($ => $ && {...$, hp: 0}), v(T), f(null), mm(), m(!1), j(!1), b(!1);
  else {                          // 普通难度：天道的仁慈
      l(!0), r(M => { ... const h = Math.max(1, Math.floor(M.maxHp * .1)),
                            R = Math.min(M.maxLifespan || 100, 10);
                      return {...M, hp: h, lifespan: R} });
      ...`${T}但天道的仁慈让你得以重...`
  }
}
```

**关键差异**：
- **硬核难度（`difficulty === "hard"`）**：真死，`hp = 0`，角色结束。
- **普通难度**：不死。**`hp` 恢复到 10% 上限，`lifespan` 重置为 `min(maxLifespan, 10)`**（即回 10 年），文案后缀「但天道的仁慈让你得以重…」。
  → 也就是说普通难度下**寿命归零只是一次「重生」**，不是终局。这解释了为什么「每轮扣寿命」不会把普通玩家玩死。

## 6. 加寿命的来源（对冲手段）

| 来源 | 效果 |
|---|---|
| **突破境界** | `_e = 硬核/普通两式`：普通为 `Math.floor((qe - maxLifespan)/9) + randInt(1..5)`；`lifespan = (lifespan ?? maxLifespan) + _e`，同时 `maxLifespan += _e` |
| 延寿丹（炼） | `effect:{lifespan:10}` → **+10 年**（千年人参×2 + 血参×3，成本 3000） |
| 长生丹（炼） | `effect:{lifespan:50}` + `permanentEffect:{maxLifespan:50}` → **+50 年、上限 +50**（成本 15000） |
| 不死仙丹（炼） | `effect:{lifespan:200}` + `maxLifespan:500` → **+200 年、上限 +500**（成本 80000） |
| 九转金丹 | `permanentEffect:{maxLifespan:1000, …全属性+1000}` |
| 千年灵芝（灵草，直接使用） | `maxLifespan:300` |
| 万年仙草（灵草，直接使用） | `maxLifespan:2000` |
| 奇遇 | 事件可带 `lifespanChange`（正负都有），UI 会打印「✨ 寿命增加 N 年 / ⚠️ 寿命减少 N 年」 |

突破公式（@629936）：
```js
const Ne = g.maxLifespan || 100;
let _e = 0;
if (m) _e = qe - Ne + Math.floor(qe * .1);
else   { const Yt = Math.floor((qe - Ne) / 9), gt = Math.floor(Math.random()*5) + 1; _e = Yt + gt; }
const st = Ne + _e, ke = (g.lifespan ?? Ne) + _e;
```

## 7. 可以动的地方（供决策，未实施）

1. **把「历练扣寿命」的系数调低或改成按时间**（`h` 那一行，一处改动）——若实测确实过猛，这是最小改动点。
2. **给普通难度加「重生宽限」**：目前重生后 `lifespan = 10`，可以抬到 `maxLifespan × 30%`，避免玩家反复在 10 年上下挣扎。
3. **把扣寿命从「每轮」改为「每天/每 N 轮」**：给 `h` 加一个计数器节流，保留紧张感但大幅降低压力。
4. **报警阈值提前**：`max(5, 上限×10%)` 可以提到 `20%`，让玩家有更多反应时间。
5. **不动**：战斗技的 `cost:{lifespan:N}` 是玩家主动选择，建议保留（它是有意义的战术代价）。
6. **不动**：离线每小时 1 年（象征性），以及各类延寿丹药（它们是对冲手段，动了会让寿命体系失去意义）。
