## 2. 心法「简单粗暴」的证据链（量化）

对 82 本心法做「攻击当量」归一：`当量 = attack*1 + defense*1.6 + hp*0.35 + spirit*2 + speed*1.8`
（权重 = 战斗 25 回合模拟里各属性的边际贡献比，与原数值无关，只用于横向比较）。

| 证据 | 数据 | 结论 |
|------|------|------|
| **① 同品级内离散极大** | 黄 38/5 = **7.6x**；玄 150/20 = **7.5x**；地 2240/48 = **46.7x**（`art-soul-forge` 炼魂诀 神800/防400 离群）；天 120000/700 = **171.4x**（`art-chaos-primal` 混沌归元功 攻20000/防15000/血80000/神15000/速10000 离群） | 同品级不存在「设计区间」，只有「手填」 |
| **② 顶端 vs 底端差 286 倍** | 天品中位 4,800 vs 黄品中位 16.8 | 82 本里 90% 是废本 |
| **③ 与境界/等级完全无关** | `Cg` 内 `t.cultivationArts.forEach(E=>{...go(N,f)...})` —— 只乘灵根倍率 `1+root*0.005` | 炼气期学到天品即可平推 |
| **④ 学习数量无上限、全量线性叠加** | 同上 `forEach` 无 `slice/filter/cap`；`Cg` 直接累加 | 最优解恒为「全学」，无取舍 |
| **⑤ expRate 无递减无上限** | `bd`：`r = u.effects.expRate * {天:2,...}`，`art-universe-devour`（吞天噬地）expRate = **1.00** ⇒ 主修 +200%；再乘缘分 `1+b` | 学满后永远挂吞天噬地 |
| **⑥ 与等级脱钩** | `is[]` 里每本心法只有静态 `effects`，没有 `level` 字段 | 「养成」维度为零 |

**⇒ 玩家的最优策略是「把所有能拿到的心法全学了，然后挂天品」，没有任何决策空间。**
这就是「简单粗暴」的完整成因。

## 3. 设计原则

1. **单元格预算**：以 `(品级, 境界需求)` 为单元格，把该单元格内所有心法的攻击当量**向实测均值收敛**（保留原侧重方向，只改量级）。
   均值即「既有设计意图的统计估计」，因此总量与现状同量级，不会推翻已上线存档的体感。
2. **门槛补偿**：有获取门槛的心法给乘数 —— `spiritualRoot ×1.15`、`buildAffinity ×1.10`、`sectId ×1.15`（可叠乘），
   让「难拿」对应「更强」，而不是随机。
3. **等级成长**：`× (1 + 0.06*(lv-1))`，满级 **+48%** —— 引入养成维度（对应证据⑥）。
4. **强度递减**：按当量降序 `× 1/(1+0.15i)` —— 第 2 本 87%、第 10 本 40%、第 30 本 18%。
   让「多学」仍有收益但边际递减（对应证据④）。
5. **修速归一**：expRate 按品级统一（黄 .10 / 玄 .16 / 地 .28 / 天 .45），主修通道再 `min(1.25, ·)`
   —— 修速是**乘法通道**，不归一就会指数爆炸（对应证据⑤）。
6. **调大产出必须同步调大服务端配额**（项目铁律，见 §5）。

### 4.2 执行公式

```
budget = CELL[grade, realmRequirement] 或 BOSS_BUDGET
budget *= (spiritualRoot?1.15) * (buildAffinity?1.10) * (sectId?1.15)
prof[k] = effects[k] * W[k]              # W = {attack:1, defense:1.6, hp:0.35, spirit:2, speed:1.8}
new[k]  = max(1, round(budget * prof[k] / Σprof / W[k]))    # 只改量级，不改侧重
new.expRate = {黄:.10, 玄:.16, 地:.28, 天:.45}[grade]
```

运行时（客户端 `is[]` 数组，模块加载即改写一次）再叠：
`× (1 + 0.06*(lv-1))` 等级成长 、`× 1/(1+0.15i)` 强度降序递减（i = 该玩家已学心法里当量降序名次）。

## 5. 经济钳制核对表 ★（项目铁律，逐项数字）

### 5.1 机制回顾

`settleSaveEconV2` 按**两次存档之间的增量**给配额，超限就把存档里的值改小：

```
capExp = min(ABS_MAX(5e9),
             floor(ECON_CLAMP_EXP_PER_MIN * mult * mins),          ← P0-1 总兜底
             floor(off.exp + dMed*medEach + dAdv*advEach + dKill*killEach + dSR*srEach
                   + min(dTowerExp, floor(E2_TOWER_EXP_PER_MIN*mult*mins) + E2_TOWER_EXP_LUMP)
                   + min(dExpedExp, floor(E2_EXPED_EXP_PER_MIN*mult*mins) + E2_EXPED_EXP_LUMP)
                   + max(100, lvlMaxExp*0.05)))

capStone = min(ABS_MAX(5e9),
             floor((floor(E2_STONE_BURST_PER_HOUR*mult*(mins/60)) + E2_STONE_BURST_BASE) * ylScale),
             floor(off.stones + dMed*((idx*2+4)*5)*ylScale + dAdv*… + dKill*… + dSR*…
                   + sellAllow*ylScale + E2_LUMP_STONE_ALLOWANCE*ylScale + 10000))
```
`mult = 1.5^realmIdx`，`ylScale = (idx<=0 ? 4/3 : 2*idx+1)/3`，`mins = max(0.5, 存档间隔分钟)`。

**为什么这是「真丢」而不是「存不进去」**：客户端 `pushSave` 收到响应后只做一件事 ——
`YLSettledExp(resp)`：`if (local.exp > resp.settledExp) setState({exp: resp.settledExp})`。
**修为被钳 = 本地修为立刻被降回去，玩家真丢。** 灵石不采纳服务端绝对值（客户端权威），
所以灵石被钳只会造成「云端存档落后于本地」，换设备/清缓存时才可见。

### 5.3 为什么是 10e6 / 6e6 这两个数

* 修为（P0-1 项）：要求 `ECON_CLAMP_EXP_PER_MIN × 1 × 0.5 ≥ 2,356,523 × 2`（2 倍安全垫）
  ⇒ ≥ 9.43e6 ⇒ 取 **10e6**（炼气档 P0-1 = 5.0M，是扫荡的 **2.12x**）。
  抬高后 `capExp` 的约束项从 P0-1 变回 `Σ各来源配额`（炼气 2,593,391），系统重新自洽。
  长生档 = min(10e6×11.39×0.5 = 56.95M, …) = **56.95M**，仍 ≪ `ABS_MAX 5e9`。
* 灵石：最坏单窗口增量 = 扫荡 938,914 + 满额出售 58,333（`min(inv*250, 1e6*mult*mins/60+5万)`）
  + 打坐/历练/击杀/秘境余量 ≈ **1.02M**。
  扫荡灵石**没有独立计数器**，只能落在 `E2_LUMP_STONE_ALLOWANCE*ylScale`（B 项）与
  `E2_STONE_BURST_BASE`（A 项）里 ⇒ 数学下限 ≈ 2.2M / 2.3M。
  本次取 **6e6**（同一数量级、便于记忆），实测余量 **2.68x**（炼气）／24.5x（长生），
  顺带修掉「长生境把整包库存卖掉 sellAllow 上限 > 旧 cap」的既有隐患。
* 两者都远小于 `ABS_MAX 5e9`，因此**不改变「单次保存增量不可达」的语义**。

  需要 P0-1 ≥ 10.44M；炼气(5M)/筑基(7.5M) 不足，**金丹档起（mult 2.25 → 11.25M）完全自洽**。
  该场景需 1.2M 攻击（≈化神以上才可能达到），已列入 §8.1 风险表。

### 7.2 发现但**本次不修**的两项（需产品决策）

**P1 · 羁绊（synergy）百分比词条全部是死数值。**
`uy` 表 10 条 synergy 合计 `attackPercent 0.90 / hpPercent 1.05 / defensePercent 0.15 /
critRate 0.35 / critDamage 0.70 / dodgeRate 0.13 / lifeLeech 0.13 / damageReduction 0.25`。
全代码库 `Pm(` 只有 4 个调用点：`Cg`（只取 flat）、`bd`（只取 `expRate`）、UI 展示 ×2。
⇒ 玩家看到「🔥 火系三绝：攻击力大增」实际只多了 400 点攻击。
**为什么不修**：修好等于给「全收集」玩家 +90% 攻 / +105% 血 / +35% 会心，是一次
**PvE/PvP 双重幂等放大**，需要配套重调数值并回归擂台/恩怨/通天塔，不适合在「明天验收」窗口内做。
**建议**：下一个版本按 `attackPercent ≤ 0.30 / hpPercent ≤ 0.40 / critRate ≤ 0.15` 重写 `uy`，
再在 `YlxwStatExtras` + `YlxwBattleBonus` 里补上消费（战斗层封顶已就位，可直接吃）。

**P2 · 远征修为不按境界缩放。**
`exp: exp` 是定值（太虚陨星 ≈ 20k~35k），而灵石走 `×YLRF`。长生境一趟 4h 只给 ~27k 修为
（打坐 1 分钟的 1/60）。**不修理由**：`YLRF` 在炼气档是 0.4444，一旦对齐就会**削弱前期远征**，
属于「改小更差」的方向；上游公式 1:1 保留更安全。建议后续单独做（把远征修为改为
`× (1 + idx*0.6)` 这类单调递增函数，而非 `YLRF`）。
