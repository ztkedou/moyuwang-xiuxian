## 1. 注入点的可用符号

### 4.4 `YlxwDirty()` 与写回刷新

监听器在 **V26E 的 C4 注入**（@614171，紧跟 `const yS=6e3,vS=30*1e3;let qg=0;` 之后，与 `jS()` 轮询同址）：

## 5. 客户端写入怎么落库

### 5.1 三层结构

| 层 | 符号 | 位置 | 职责 |

### 5.2 写入路径（实测）

```
本地改 player（setPlayer / 直接改 state）
   │
   ├─(A) 10 秒自动推： bS() @613612
   │     setInterval(()=>{ if(YLSync.isBlocked())return;
   │       const c=Be.getState(); if(!Et.getState().isAuthenticated||!c.player)return;

   │                     timestamp:d,lastActiveTime:d})
   │         .catch(f=>{ /* 300s(gS=300*1e3) 节流后 Je("云端自动保存失败…") */ })
   │     }, 1e4)                       // ← 10 秒
   │
   ├─(B) 仙务写动作： YlxwDirty() → window "yl-xw-dirty" 事件
   │     → 监听器 @614171 → YLSync.push({player,logs,marketItems,timestamp,lastActiveTime})   // 立即推
   │
   └─(C) 手动保存： j4 的保存按钮 @731847 附近 → Pn.pushSave({player:P.player,logs:P.logs,timestamp})
   
YLSync.push(payload)
   └─ POST {ln}/save   ← 实际由 Pn.pushSave 发出（push 内部调用）
        Xc 会自动带 Authorization: Bearer <token> + X-YL-Base-Revision: appliedGmRevision + X-YL-Session: __ylSid
        · 409 session_superseded → YLSync.setBlocked(!0)，抛「此账号已在其他设备打开」
```

`Pn.pushSave` 实测（@601280）：`t.dungeonGate=window.__ylDg||null; t.settings=Be.getState().settings;` 然后 `await Xc(\`${ln}/save\`, {method:"POST", …, body:JSON.stringify(t)})`。
`Pn.fetchSave`（@600483 起）：`await Xc(\`${ln}/save\`)`，读响应头 `x-yl-gm-revision` → `Be.getState().setAppliedGmRevision(...)`；返回整个存档 json。
`Pn.fetchRevision`：`await Xc(\`${ln}/save?revision=1\`)` → `{gm_revision, updated_at, has_save}`。

### 5.3 `applyRemoteSave` / `gm_revision` / `appliedGmRevision` —— **存在**

- `applyRemoteSave`：`Be` 的 action，@545390：
  `applyRemoteSave:(a,l)=>{if(!(!a||!a.player))try{const c=ho(a.player); t({player:c, logs:(a.logs||[]).slice(-1000), gameStarted:!0, hasSave:!0, appliedGmRevision:typeof l=="number"?l:r().appliedGmRevision}), di(c,a.logs||[],Ze.getState().marketItems), a.marketItems&&Ze.getState().setMarketItems(a.marketItems)}catch(c){console.error("应用云端存档失败:",c)}}`
- `appliedGmRevision`：`Be` 初始 `0`（@544053），setter `setAppliedGmRevision`（@544448）。
- 轮询：`jS()` @614514，`setInterval(…, yS=6e3)` —— 每 **6 秒** `Pn.fetchRevision()`，若 `gm_revision > max(a.current, appliedGmRevision)` 且 `!YLSync.isBusy()` → `Pn.fetchSave()` → `applyRemoteSave(u, d.gm_revision)`；提示节流 `vS=30*1e3`（30 秒最多弹一次「检测到云端数据已更新…」）。
- 服务端权威 + 防倒滚由 `X-YL-Base-Revision` + `X-YL-Session` + 409 自愈实现（`YL_SERVER_AUTH_V26I` 块）。

### 5.4 ★ 新增「纯客户端系统」的正确写入姿势

**结论：改 `player` 的新字段，不需要任何额外代码 —— 直接改本地 player，10 秒自动推 / 或主动 `YlxwDirty()` 立即推，即可落库。**

推荐写法（按优先级）：

1. **写**：`Be.setState({player:Object.assign({}, Be.getState().player, { 你的新字段: v })})`
   —— 或沿用 store 的 `setPlayer(fn)`：`Be.getState().setPlayer(p => ({...p, 你的新字段: v}))`。
   `ho()` 用 `...t` 展开，**未知字段原样保留**，所以新字段随整包 JSON 往返不丢。
2. **立即落库**：`YlxwDirty()`（dispatch `yl-xw-dirty`）→ 监听器 `YLSync.push(整个 player)` → `POST /yl/api/save`。
   —— 若你的系统不走仙务块，可自己 `window.dispatchEvent(new Event("yl-xw-dirty"))`，**复用既有监听器**（零新增同步代码）。
3. **不需要**：手写 `fetch`、不需要自己拼 token、不需要自己处理 409（`YLSync.push` 已串行化 + 冲突自愈）。
4. **HUD 刷新**：本地 state 改完 React 自然重渲染；跨端一致由 `gm_revision` → `jS()` 6s 轮询 → `applyRemoteSave` 兜底。
5. **服务端**：`POST /api/save` 把整个 `player` 存进 `saves.save_data`，**服务端不认识的新字段会原样存下**（`settleSaveEconV2` 只处理经济字段）。**所以纯客户端系统无需服务端改动。**
6. **若需要发奖/扣费**：走既有的经济端点（`spiritStones` 由服务端 `settleSaveEconV2` 钳制 + `YLApplyBalance` 回显），**不要**在客户端直接改 `spiritStones` 后推 —— 会被服务端钳制回滚（这是设计如此）。

## 7. 注入块的技术约束（门禁）

### 7.1 原方案（v26d/v26e 文档）定的规则

1. **中文一律 `\uXXXX`**（注入块内非 ASCII 全部转义）。
2. **复用 `e.jsx` / `e.jsxs` 运行时**，不引 React.createElement 之外的东西。
3. **禁止 `fetch` 直连** —— 必须走 `Xc`（带鉴权）/ `YlxwApi`。
4. **禁止读写 token 存储键**（`auth_token`、`yl_*_token`、`sessionStorage`）。
5. **禁止 `iframe` / `postMessage`**。
6. **每个锚必须 `count==1`**（`str.replace` 前断言，任一失败中止不落盘）。
7. 全包门禁额外项：`auth_token` 裸串恰 =1 且 offset<5000；`getItem("auth_token")`/`setItem("auth_token"` =0；`yl-app-dirty`=0；`ylOpenApp`=0；`postMessage` 不进全包门禁（基线 1 次为 React scheduler）。

### 7.3 新增注入块**必须遵守**的（我给出的结论）

**必须遵守（硬）**：

1. **每个锚 `count==1`**，构建脚本先断言再替换，失败中止不落盘。
2. **中文一律 `\uXXXX`** —— 注意这是**注入块内**的规范；**本体部分的中文是裸 UTF-8**，所以锚定本体文案时锚串要写**裸中文**（如 `title:"秘境探索"`），而注入的新代码要写转义。
3. **复用 `e.jsx/e.jsxs` + `O`（React）**，不要引入新的 jsx 运行时。
4. **禁止 `fetch` 直连**，走 `Xc`（自动鉴权/刷新/会话头）或 `YlxwApi`。
5. **禁止读写 token 存储键**（`auth_token`、`yl_*_token`、`sessionStorage`）—— 全包这些键的读写点已收敛到本体，注入块内必须为 0。
6. **禁止 `iframe` / `postMessage`** —— 旧 `#app-overlay` 壳层协议已退役（`yl-app-dirty`/`ylOpenApp` 均为 0），不得复活。
7. **新增模态键必须同步三处**：`Sg`（初始值，`closeAllModals` 靠它复位）+ `closeCurrentModal` 优先级链（Esc 可关）+ **`f1()` 的 `||` 链（否则整个模态层不渲染，B1 教训）**。
8. **注入块内禁止中文裸串**、禁止 `document.write`、禁止改 `document.body.style.overflow`（`ct` 自己管）。

**建议遵守（软）**：

- 新块紧贴 `/* == end YL_XIANWU_V26F extras == */` 之后、`function $4(` 之前插入，保持「块栈」可读。
- 用 `\uXXXX` 时注意 `\u` 在 python 字符串里要写 `chr(92)+"u%04x"`，避免转义踩坑（本仓库脚本 `xianwu_fix.py` 已有 `esc_zh()`/`rx_of()` 工具可直接复用）。
- 写动作统一「`Xc` POST → `ia()`/`Je()` → `load()` → `YlxwDirty()`」四步，保证 HUD 同步。
- 二跳发奖类复用 `YlxwMailHint` + `go("mail")`。
- 新块体量若 >100KB，考虑按 tab 拆分懒渲染（`O.lazy` 会改变 chunk 结构，**当前单 bundle 前提不能动**）。

## 8. 风险 / 未解项（如实说明）

1. **`YlxwHub`（全屏枢纽，左侧分组栏）当前未被挂载** —— 生效的是 `YlxwPanelModal`（单 tab）。若上游新系统需要「枢纽式」全屏入口，需要新加一条挂载（可在 `QM` 体内 `d.isXianwuOpen&&e.jsx(YlxwHub,…)`，锚点 `d.isXianwuOpen&&e.jsx(YlxwPanelModal,{` @1200186，count=1）。
2. **入口锚点已漂移**：v26e 文档里的两个入口锚在 v26m 上**已失效** ——
   - `hidden md:flex gap-2 flex-wrap`（C6b 顶栏锚）：**count=0**。当前顶栏容器是 `hidden md:flex gap-1 flex-wrap items-center justify-end flex-1 min-w-0` @735723（`gap-2`→`gap-1`），且仙务入口已改成 27 处 `YlxwOpen("xxx")` 按钮（@736539…743533）直接插在 `j4`（顶栏组件 @731847）里。
   - `md:grid-cols-6`（C5 底栏第 6 格）：**count=0**。底栏 `N4`（@744905）仍是 `border-t border-stone-700 grid grid-cols-3 md:grid-cols-5` @745178，**没有第 6 格**；仙务入口实际走的是 `N4` 内的抽屉列表 `C=O.useMemo(()=>[{icon:sm,label:"属性",…},{icon:YlxwMk("mail"),label:"信箱",…},…])` @750604 起（14 处 `YlxwMk`）。
   → **新系统加入口时，不要照抄 v26e 文档的 C5/C6b 锚，要用本文件 §6 的锚。**
3. **`statistics` / `grotto` 等子对象**：`ho` 会重建默认值，若上游系统在这些子对象里加字段，要自己补默认值，否则首次读入可能被默认值覆盖（`grotto` 的 `...t.grotto` 展开是保留的，`statistics` 不是）。
4. **`applyRemoteSave` 会整包替换 player** —— 如果上游系统的字段**只在客户端内存里、没推给服务端**，被远端存档覆盖时会丢。所以纯客户端系统**必须走 push**（10s 自动 / `YlxwDirty`）。
5. **`xianwuTitle` 是服务端入档字段**（`title/equip` 端点），纯客户端新增字段不走这条，无影响。
6. 没有发现「必需符号缺失」：`O/e/ct/Xc/ln/Pn/Be/Ze/Et/ia/Je/Ui/Hl/an/ho/fe/YLSync/YLApplyBalance/Rt/xd/Sg` **全部实测存在且 count=1**。
