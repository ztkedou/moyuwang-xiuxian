# 装备掉落「按境界限制等阶」概率模型与改法

> 目标：全局优化掉落，使**同阶装备正常、高 1 阶小概率、高 2 阶近乎为 0、高 3 阶及以上绝对不可能**。
> 本文只做方案与精确代码片段，**不改 bundle**（bundle 由 team-lead 修改）。

## 1. 其他游戏的常见做法（调研）

| 做法 | 代表 | 机制 | 优点 | 缺点 |
|---|---|---|---|---|
| **A. 硬性等级门槛**（Hard prerequisite / level requirement） | WoW 物品等级需求、Diablo 系列 `level requirement`、通用 RPG 的 `reqLevel` | 装备带 `reqLevel`；玩家等级 < 需求 → 该装备**直接从掉落池剔除** | 实现最简单、绝不会掉出无法穿戴的装备、不会污染背包 | 二值化，没有「欧皇爆高级货」的惊喜感 |
| **B. 等级分带 / 池分段**（Level band / tier pool） | 经典 ARPG、多数手游掉落表 | 掉落池按等级段切分，玩家从「本段 ±1 段」中抽取 | 曲线可控、好调 | 分段边界处体验跳变，需要维护多张表 |
| **C. 动态权重衰减 + 硬上限**（Dynamic weight decay + hard cap） | Diablo3 的 ilvl 分布、PoE 的 ilvl 权重、本文方案 | 装备权重 = `f(装备阶 - 玩家阶)`，越离谱权重越低；**超出上限直接权重 0** | 平滑、既有小概率惊喜又不会越级离谱；可精细调控 +1/+2 概率 | 需要一次数值调参 |
| **D. 标签查询过滤**（Tag/query filtering） | 现代引擎「Smart Loot」 | 物品打 `Tier/Level/Skill` 标签，开箱时按玩家属性动态查询子集 | 灵活、可扩展多维度 | 架构成本高，对压缩单文件包偏重 |

参考：[How to Scale Procedural Loot to Player Skills](https://salivity.github.io/game-development/article/how-to-scale-procedural-loot-to-player-skills)（动态权重 / 标签查询 / 严格门槛 / 保底槽）、[How to Balance Procedural Loot Drops in RPGs](https://salivity.github.io/game-development/article/how-to-balance-procedural-loot-drops-in-rpgs)。

> 本游戏其实已有先例：冒险事件 `Fm()` 里就用 `b>=fe.indexOf(ae.SpiritSevering)` 之类的**境界硬门槛**来过滤事件。本次只是把同样的思路补到装备掉落上。

**本方案选用 C（动态权重衰减 + 硬上限）**：改动最小、可精确给出 +1/+2 概率、天然满足「高 3 阶不可能」。

## 2. 概率模型

### 2.1 定义

- 玩家境界序 `v = fe.indexOf(a)`（`a` 为玩家当前境界字符串）
- 装备境界序 `i = fe.indexOf(q.realm)`；若装备无 `realm`（草药/丹药/材料/合成石等），视为**不受限**（等价 `i = v`）
- 相对偏移 `d = i - v`

### 2.2 权重表

| 相对偏移 `d` | 含义 | 权重 `w(d)` | 说明 |
|---|---|---|---|
| `≥ +3` | 高 3 阶及以上 | **0** | **硬排除，永不出现** |
| `+2` | 高 2 阶 | **0.4** | 「几乎为 0」 |
| `+1` | 高 1 阶 | **4** | 「还有一点可能」 |
| `0` | 同阶 | **40** | 正常、绝对主力 |
| `-1` | 低 1 阶 | 8 | 保留，权重递减 |
| `-2` | 低 2 阶 | 2 | 保留 |
| `≤ -3` | 低 3 阶及以上 | 0.3 / 每档 | 保留但很罕见 |

> 权重 = 抽样相对权重。由于装备池在每个 `(realm, rarity)` 组合上的条目数**相等**（`WN()` 对每个境界都生成相同的部位×变体），所以在固定品质过滤后，`P(d) ∝ w(d)`，权重可直接当作概率比例。

### 2.4 三个设计问题的回答

1. **是否保留低于自身境界的装备？** —— **保留**，但权重递减（-1 → 8，-2 → 2，≤-3 → 0.3/档）。这样高境界玩家仍会掉落少量低阶物（合理、可用于分解/合成），但同阶始终占 ~72~90%。若想彻底只掉同阶及以上，把 `d<0` 的权重全设为 0 即可（见 §5 调参）。
2. **限制作用于装备类掉落池还是也影响品质 roll？** —— **只作用于装备类掉落池**（武器/护甲/首饰/戒指/法宝，即 `gs.weapons/armors/accessories/rings/artifacts`）。草药/丹药/材料/装备合成石/丹方**不受影响**（它们没有 `realm` 字段，权重恒等 → 行为与原来完全一致）。**品质 roll（`T()`）完全不动**：先摇品质，再用境界权重选具体物品。这样「炼气期也能出仙品」的手感保留，但仙品只会是炼气/筑基/金丹的仙品，不再是长生境仙品——正是要修的漏点。
3. **高 3 阶以上如何硬性排除？** —— 两处保证：① 两个 `filter` 谓词里加 `_ri(q)<3`（把 `d≥3` 的装备直接踢出候选集）；② 权重函数 `_rw` 对 `m>=3` 返回 `0`（即使漏进候选也不会被选中）。**双保险，绝对不可能**。

### 3.4 改动说明

- **新增 `_ri(q)`**：返回该物品相对玩家的境界偏移 `d`；`q.realm` 缺失时退回 `q.realmRequirement`；两者都无（草药/丹药/材料/合成石）时按「同阶」处理（偏移 0）→ 不受限制。`v<0` 时钳到 0，避免玩家境界异常导致误杀。
- **新增 `_rw(q)`**：把偏移映射为权重，`m>=3` 返回 0（硬排除）。
- **两个 filter** 各加 `_ri(q)<3 &&`：把高 3 阶及以上装备从候选集剔除（第一路：精确品质；第二路：品质 ≤ 目标品质的兜底）。
- **`mi(g)` → 加权抽样 IIFE**：按 `_rw` 权重抽取。对非装备池（权重全相等）退化为等概率，与原来行为一致。
- **未改动**：品质 roll `T()`、丹方分支（`k.type==="recipe"` 走 `continue`，本就不经过此处）、护甲部位选择 `mi(q)`（`q` 是部位数组，不受影响）、去重集合 `d`、返回结构。
- **变量命名**：全部使用 `_` 前缀（`_ri/_rw/_p/_t/_z/_s/_e/_b`），与 `_y` 作用域内既有变量（`c,d,u,f,v,j,b,S,x,T,$,M,h,R,E,N,k,_,C,g,q,w,A`）**无冲突**；`for` 循环体内 `const` 每轮重建绑定，合法。

## 4. 验证方法

### 4.1 模型级验证（推荐，快、可复现）

把下面的 Node 脚本存为 `verify_drop.js`，直接跑，验证 §2.3 的概率表：

```js
// verify_drop.js  —— node verify_drop.js
const names=['炼气期','筑基期','金丹期','元婴期','化神期','合道期','长生境'];
const w=d=>d>=3?0:d<=-3?0.3:d===-2?2:d===-1?8:d===0?40:d===1?4:d===2?0.4:0;
function pick(v){ // 与 bundle 中加权抽样等价：每档 bucket 大小相同 => 权重即比例
  const ws=names.map((_,i)=>w(i-v)); const s=ws.reduce((a,b)=>a+b,0);
  let b=Math.random()*s;
  for(let i=0;i<ws.length;i++){ if((b-=ws[i])<=0) return i; }
  return names.length-1;
}
const N=1e6;
for(let v=0;v<7;v++){
  const cnt=new Array(7).fill(0);
  for(let i=0;i<N;i++) cnt[pick(v)]++;
  console.log(names[v].padEnd(4), cnt.map(c=>(c/N*100).toFixed(2)+'%').join(' '));
```

## 5. 调参与回滚

### 5.1 调参（只改 `_rw` 里的数字，均为 ASCII）

| 目标 | 改法 |
|---|---|
| 高 1 阶更稀有 | `m===1?4` → `m===1?2` |
| 高 2 阶更稀有 | `m===2?.4` → `m===2?.2` |
| 完全不要低阶装备 | `m<=-3?.3` → `m<=-3?0`，且 `m===-2?2`→`0`、`m===-1?8`→`0` |
| 只允许同阶 | 仅保留 `m===0?40`，其余全 `0` |
| 允许高 3 阶（若日后想放宽） | 把两处 `_ri(q)<3` 改成 `<4`，并在 `_rw` 增加 `m===3?...` 档 |

> 注意：`_ri(q)<3` 与 `_rw` 的 `m>=3?0` 是**硬上限双保险**。放宽上限必须两处同改。

### 5.2 回滚

把 §3.3 的替换后片段换回 §3.2 的替换前片段即可，唯一锚点、无副作用。
