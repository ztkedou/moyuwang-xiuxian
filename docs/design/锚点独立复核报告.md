## 2. 发现的问题（与文档不一致处，逐条）

### #1 ❌【最严重】P8a / P8b 的 `b` **不是玩家**，是商店对象

**文档原文**：`handleSellItem:(R,E)=>{b&&m(N=>{...})}`（`b` = 玩家）。

**实测**（@1202157 起的 `FM` 函数头）：

```js
function FM(t){
  const r=Be(R=>R.player), a=Be(R=>R.setPlayer), l=Be(R=>R.addLog),
        c=Ze(R=>R.currentShop), d=Ze(R=>R.setCurrentShop),
        u=Ze(R=>R.setModal), f=Ze(R=>R.setPurchaseSuccess),
        v=r, m=a, j=l, b=c, S=d, x=..., T=f;
```

- `b = c = Ze(R=>R.currentShop)` ⇒ **`b` 是商店对象**（证据：同函数 `handleBuyItem` 里用 `b.reputationRequired`、`b.items`）。
- 回调内的玩家是 **`N`**（`m(N=>{ ... N.equippedItems / N.inventory / N.spiritStones ... })`）。
- 玩家对象持有 `inventory`，**不持有 `items`**；`b.items.find(U=>U.name===R.name)` 说明 `b` 是商店货架。

**后果**：`YLRF(b)` 会走 object 分支取 `b.realm`（`undefined`）⇒ 返回 `1`。于是
`Math.floor(q*w*50*YLRF(b)/3)` ≡ `Math.floor(q*w*50/3)` —— **出售价被整体砍到 1/3，且完全没有境界曲线**。不报错，静默错。

**修正**：`YLRF(b)` → **`YLRF(N)`**（P8a、P8b 都在 `m(N=>{...})` 回调内，`N` 可见）。

### #2 ❌【严重】P5 的 `YLRF(m.realm)` 传的是**字符串**，`YLRF` 只认 number / object

**文档 P0 的 `YLRF` 实现**：

```js
function YLRF(j) {
  var i = -1;
  if (typeof j === 'number') { i = j; }
  else if (j && typeof j === 'object' && j.realm != null) { i = fe.indexOf(j.realm); }
  if (!(i >= 0)) return 1;
  ...
}
```

**只接受**：`number`（境界下标）或 **带 `.realm` 的对象**（玩家）。
**不接受**：`string`（如 `"炼气期"`）。

**文档 P5 的 new** 却写的是 `YLRF(m.realm)` —— `m.realm` 是**境界字符串** ⇒ `typeof === 'string'`、非 object ⇒ `i` 保持 `-1` ⇒ **返回 `1`**。

于是 P5 的实际效果 = `Math.floor(基数 / (1 + 0.5×idx))`，**只有下调、没有任何境界曲线**，与文档 §3 表格里 P5「新值@金丹 14,717 / 新值@长生 38,274」完全不符。

**修正**（二选一）：
- **首选**：`YLRF(m.realm)` → **`YLRF(m)`**（`m` 是 `r(m=>{...})` 回调内的玩家对象，object 分支可用）。
- 或：`YLRF(fe.indexOf(m.realm))`。

> 注：`m` 本身是对的（`claimQuestReward:v=>{r(m=>{... m.dailyQuests ...})}`），只是**传参形态**错了。

### #3 🔶 `YLS` 与既有全局 `YLSync` 前缀相同 —— 方案自设判据会误报（**非真冲突**）

**实测**：
- `\bYLS\b`（词边界独立标识符）= **0 次** ⇒ 严格说 **`function YLS(j,b){}` 不会撞名**，是合法 JS。
- 但子串 `YLS` = **15 次**，全部来自既有全局对象 **`YLSync`**（`var YLSync = {...}` @595116，15 处；`YLSyncBanner` 3 处）。

**问题**：任务/方案自定的验收判据是「新标识符出现次数必须为 0」。用 `s.count("YLS") == 0` 做断言会**直接失败**（15 ≠ 0），补丁脚本会中止。且 `YLS` 与 `YLSync` 家族高度混淆。

**另注**：`YLS` 在 P1~P18 的 `new` 片段里**从未被调用**，P0 里定义了但没人用。

**修正**：把 `YLS` 改名为 **`YLStoneGain`**（或直接删除该函数）。改名后 `s.count("YLStoneGain")` = 0，断言可过。

### #4 ⚠️ P5 的 `new` 还有一处**潜在除零以外的语义偏差**（提示，非阻塞）

`Math.max(0, fe.indexOf(m.realm))` 在 `m.realm` 不在 `fe` 中时返回 `-1` ⇒ `Math.max(0,-1)=0` ⇒ 除数 `1`，不会除零 ✅。
但此时若把 `YLRF(m.realm)` 改成 `YLRF(m)`，未知境界会得到 `YLRF=1` ⇒ `S = 基数`（**比现状 `基数×5` 少 5 倍**）。这是「未知境界」的极端边界，文档未讨论，**建议确认是否接受**。

### #5 🔶 P15b 服务端口径与客户端 `YLRF` 不一致

文档 P15b 的 new：`(idx <= 0 ? 4 / 3 : 2 * idx + 1) * 125`。

而客户端 `YLRF` 的规格是：`i < 0 → 1`、`i == 0 → 4/3`、`i >= 1 → 2i+1`。

服务端 `idx = R.indexOf(String(p.realm||''))`，**境界未识别时为 `-1`**，此时服务端给 `4/3`、客户端给 `1` —— 两者在「未知境界」档不一致（筑基及以上一致）。

**修正建议**：服务端写成 `(idx < 0 ? 1 : idx === 0 ? 4/3 : 2*idx+1)`，与 `YLRF` 严格同源。
（`srv/index.ts` 中该 old 片段实测 **count = 1**，@63132，可用。）
