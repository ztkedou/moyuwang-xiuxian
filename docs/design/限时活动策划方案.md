# 摸鱼修仙传 · 限时活动策划方案

> 设计原则：**奖励一律按「境界时薪」折算，用「相当于挂机多少小时」做标尺**，彻底取代现有的一次性固定值（奇遇 63 灵石 ≈ 挂机 1 秒）。所有结算在服务端完成。

## 0. 同类产品调研结论

| 产品 | 代表活动 | 周期 | 关键做法 |
|---|---|---|---|
| 一念逍遥 | 探宝周 / 兽潮 / 月活 | 每月 1 次，持续 7 天 | 活动道具可跨期囤积；奖励按抽数分档解锁（30/100/450） |
| 最强祖师 | 魔域争锋（赛季+限时） | 赛季 14 天 | 5 阶段全服累计推进；军需官代币商店；4 类排行榜 |
| 最强祖师 | 九层妖塔 / 仙途试炼 | 21 天/期，持续 7 天 | 白嫖可拿保底档；榜一给自选珍稀 |
| 通用放置类 | 开服冲榜 / 节日签到 / 累充累消 | 3~14 天 | 固定档位+进度条；签到第 7 天给大奖 |

**共性四条**：① 短活动 3 天、长活动 7~14 天；② 双轨发奖＝进度档位（保底）+ 排行榜（拉开差距）；③ 用「活动代币兑换」而非直接发固定值，避免贬值；④ **让老玩家不觉得鸡肋的唯一办法＝奖励随境界/进度缩放**，或给可囤积的通用代币。

## 2. 活动方案

### 方案一：天降灵雨（在线灵石倍率节）—— 优先级 P0 / 难度 低
| 项 | 内容 |
|---|---|
| 周期 | 3 天（周五 20:00 — 周一 20:00），每两周一次 |
| 玩法 | 窗口内**在线**打坐/历练灵石产出 ×2，离线不计 |
| 发奖 | 服务端每 10 分钟读 `stats_daily.minutes` 差值，`bonus = 境界时薪 × 在线分钟/60 × 1`，累积满 1 小时后经 `mail.attached_lingshi` 发放 |
| 奖励量 | 按日在线 2h 计，单日 = 2h 挂机；3 天合计 = **6h 挂机**（= 时薪 ×6） |
| 技术改动 | 服务端：复用 `events`（新增 type `stones2_live`）+ `stats_daily` + `mail`，新增定时结算器；`activity_config.engine_on` 作 kill switch。客户端：仅拉活动横幅（`/api/activity/list` 已存在） |
| 防刷 | 单日结算上限 = 时薪 ×8（8h）；不足 10 分钟不结算；口径用 minutes 而非 silver_gain，**天然防自激**（发的奖不会被下一轮算进去） |

### 方案二：仙途冲榜（限时排行榜）—— 优先级 P1 / 难度 中
| 项 | 内容 |
|---|---|
| 周期 | 7 天，第 7 日 0 点结算发奖 |
| 玩法 | 窗口内累计「灵石获取」与「击杀数」双榜（数据源 `stats_daily` 窗口聚合） |
| 奖励 | 第 1 名 **12h**；2~3 名 **8h**；4~10 名 **5h**；前 30% **2h**；参与（>10min）**0.5h**。全部按时薪折算 |
| 技术改动 | 服务端：新增 `/api/activity/rank`（`stats_daily` 聚合 + `rankings` 快照），结算后走 `mail` + `chronicle` 公告；客户端：新增榜页（可复用现有排行榜组件） |
| 防刷 | 唯一口径为 `stats_daily`（服务端埋点，不可伪造）；同账号多角色不合并；榜单窗口按北京时区 |

### 方案三：节庆签到（7 日登录）—— 优先级 P1 / 难度 低
| 项 | 内容 |
|---|---|
| 周期 | 7 天，每日 0 点刷新 |
| 玩法 | 每日登录点一次领奖，7 天全勤额外大奖 |
| 奖励 | 第 N 天 = 时薪 × (N/6) 小时；第 7 天 **3h** + 全勤额外 **3h**；7 天合计 ≈ **7h 挂机** |
| 技术改动 | 服务端：新表 `activity_checkin(player_id, activity_id, day, claimed_at)`，PK 约束防重复；发奖走 `mail` 或直发；客户端：签到页 |
| 防刷 | 每活动每玩家每日仅 1 次（PK 兜底）；跨日按北京时区，与 `daily_quests` 同口径 |

### 方案四：灵玉阁（限时代币兑换）—— 优先级 P1 / 难度 中
| 项 | 内容 |
|---|---|
| 周期 | 14 天 |
| 玩法 | 活动期打坐/历练/爬塔/秘境掉落代币「灵玉」，在活动商店兑换 |
| 奖励 | 灵石袋：小 100 玉 = **1h**；中 300 玉 = **4h**；大 800 玉 = **12h**（按境界发放）。代币可跨期囤积 |
| 技术改动 | 服务端：新表 `activity_token`（余额）+ 商店定义；扣减用守卫式 `UPDATE ... WHERE balance>=?`；客户端：商店页 + 掉落入包提示 |
| 防刷 | 打坐掉 1 玉/次、**日上限 300 玉**；单活动累计上限 4200 玉；代币不可交易 |

### 方案五：天魔降世（限时世界 BOSS）—— 优先级 P2 / 难度 高
| 项 | 内容 |
|---|---|
| 周期 | 7 天，每日 20:00—22:00 开放 |
| 玩法 | 全服共讨「天魔」，按累计伤害排名 |
| 奖励 | 伤害档位 + 排名奖，最高 **12h** 挂机，全服击破额外全服奖 **2h** |
| 技术改动 | 服务端：新表 `activity_boss`（血量/伤害记录）+ 挑战端点；客户端：战斗入口 + 血条 |
| 防刷 | 每日挑战 3 次；伤害上报由服务端按战力上限校验 |

## 3. 结论：只做 1 个，做方案一「天降灵雨」

理由：① 复用已落地的 `events` / `activity_config` / `stats_daily` / `mail` 四张表与活动引擎，**几乎零客户端改动**，一天内可上线；② 直接命中现状痛点——把奖励从「挂机 1 秒」拉到「挂机 2 小时/天」；③ 按时薪折算，天生随境界缩放，老玩家不鸡肋；④ 结算口径用服务端 `minutes` 差值，无自激、无刷子空间。

落地顺序建议：**方案一 → 方案三 → 方案二 → 方案四 → 方案五**。
